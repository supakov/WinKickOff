# Конструктор установки Windows для рабочих групп. Черновик постановки задачи

Статус: черновик 0.1 от 12.09.2026. Исторический документ: с 25.09.2026 постановка и план ведутся
в `../draft/install-editor/` (Python 3.14, tkinter, портабельное приложение). Раздел 6 «Открытые
вопросы к заказчику» остаётся актуальным.

## 1. Контекст и цель

Малые организации без домена Windows: 3-30 ПК, локальные учётные записи, общие папки и принтеры,
за компьютерами непрофессионалы, штатного специалиста по безопасности нет. Страна находится под
постоянными кибератаками государства-агрессора, атаки идут непрерывно, а специалистов не хватает.

Цель: инструмент с графическим интерфейсом, который по ответам на понятные вопросы собирает
`autounattend.xml`. Установка с этим файлом даёт защищённую, обновляемую, предсказуемую систему,
которую можно поддерживать без глубоких знаний. Базовая версия файла (v0.1 в этом репозитории)
служит эталоном того, что конструктор должен уметь генерировать.

## 2. Принципы

1. Безопасность по умолчанию. Любая настройка, ослабляющая защиту, требует явного действия и показывает предупреждение.
2. Ничего не скачивается из интернета во время и после установки. Всё, что нужно, лежит в одном файле.
3. Никаких сторонних утилит и «оптимизаторов». Только штатные средства Windows: политики в реестре, PowerShell 5.1, DISM.
4. Всё, что делает установка, записано в логи на диске и может быть отменено по документированной инструкции.
5. Минимум вопросов при установке: осознанно остаются выбор диска и язык установщика.
6. Косметика (темы, панель задач, контекстные меню) отделена от базового профиля и по умолчанию выключена.
7. Компоненты, которые нужны для обслуживания системы, не удаляются никогда: Microsoft Store, winget, Edge, Windows Update, Defender, Spooler, службы смарт-карт (токены ЭЦП).

## 3. Архитектура результата

Выходной файл состоит из трёх слоёв:

1. XML-шаблон: проходы windowsPE, specialize, oobeSystem. Конструктор меняет в нём учётные записи,
   языки ввода, регион, часовой пояс, имя компьютера, ключ и редакцию, обход проверок железа.
2. Блок `$Config` в начале `Setup-System.ps1`: набор переключателей с комментариями. Это основной
   продукт конструктора. Код скриптов ниже блока не меняется от профиля к профилю.
3. Три скрипта с фиксированными ролями:
   - `Setup-System.ps1`: машина, выполняется один раз от SYSTEM в specialize;
   - `Setup-User.ps1`: пользователь, выполняется через Active Setup один раз при первом входе каждого;
   - `Post-OOBE.ps1`: очистка после завершения OOBE, самоудаляется.

Конструктор должен уметь показать «дифф» между двумя профилями и экспортировать профиль в JSON,
чтобы настройки были воспроизводимы и проверяемы.

## 4. Разделы параметров

Для каждого параметра указано значение по умолчанию v0.1 и причина.

### 4.1 Установка

| Параметр | По умолчанию | Примечание |
|---|---|---|
| Редакция | Pro | Универсальный ключ выбирает редакцию без окна |
| Ключ продукта | не спрашивать | Активация по цифровой лицензии железа; поле для ввода ключа опционально |
| Обход TPM/Secure Boot/CPU/RAM | включён | Для старого парка; на совместимом железе не ослабляет |
| Разметка диска | ручная | Автоматическая стирает диск, для рабочих ПК недопустимо без явного согласия |
| Язык установщика | из ISO | Зависит от образа, спрашивать пользователя конструктора |
| .NET Framework 3.5 с носителя | включён | Нужен старым программам |
| Имя компьютера | случайное | Опция: шаблон с префиксом организации |

### 4.2 Учётные записи

| Параметр | По умолчанию | Примечание |
|---|---|---|
| Администратор | Admin, группа Administrators | Имя редактируется |
| Пользователь | User, группа Users | Можно несколько |
| Пароли | пустые: стартовые учётные записи | Пароли, дополнительных пользователей и группы назначает отдельный проект после установки. Если в файле когда-нибудь появится пароль, он хранится открытым текстом, поэтому Post-OOBE обязан удалять копии |
| Срок действия пароля | не истекает | Иначе через 42 дня Windows требует смену |
| Блокировка после неверных паролей | 10 попыток, 15 минут | |
| Автоблокировка экрана | 15 минут простоя | |
| Встроенные Administrator и Guest | отключены | Проверяется после OOBE |
| Автовход | запрещён | Не предлагать вообще |

Стыковка с проектом управления пользователями. Установка создаёт только стартовые Admin и User и ничего
не делает с паролями и группами сверх этого. Отдельный проект добавляет пользователей, принудительно
назначает пароли и группы. Для него установка должна оставить чистую точку входа: учётные записи с известными
именами, снятый срок действия пароля, отсутствие политик паролей в файле ответов (их задаёт тот проект),
логи в `C:\ProgramData\Unattend`. Формат передачи (скрипт после установки, задача планировщика, запуск вручную)
согласовать с тем проектом.

Открытый вопрос: запрет сетевого входа для локальных администраторов (защита от горизонтального
перемещения). Мешает удалённому администрированию своим же админом. Предлагается как опция «строгий режим».

### 4.5 Microsoft Defender

Три уровня в интерфейсе конструктора:

| Уровень | Что включено |
|---|---|
| Базовый | Всё, что Windows включает сама; никаких ослаблений |
| Усиленный (по умолчанию) | Облачная защита High, отправка безопасных образцов, PUA, сетевая защита, 15 правил ASR в режиме блокировки, 2 в аудите/предупреждении |
| Строгий | Плюс контролируемый доступ к папкам, правило «редкие исполняемые файлы» в блокировку, SmartScreen Block |

Правила ASR перечислены в `$AsrRules` с GUID и комментарием. Для Office-правил нужен установленный
Office в стандартном пути, иначе они просто не срабатывают.

### 4.9 Приложения

Два списка в интерфейсе: «удаляется» (чекбоксы) и «сохраняется всегда» (без чекбоксов).
Список по умолчанию в `$AppsToRemove`. Кандидаты на отдельные чекбоксы: новый Outlook, Phone Link,
Teams, Quick Assist, Clipchamp, Медиаплеер, Камера.

### 4.10 Печать

Spooler всегда Automatic. Установка драйверов принтеров только администратором (защита от PrintNightmare).
Следствие: сетевой принтер с новым драйвером подключает Admin, а не User. Опция «разрешить пользователям
подключать принтеры с сервера X» для сетей с принт-сервером.

### 4.11 Удалённый доступ

Удалённый помощник, входящий RDP, удалённый реестр выключены. Quick Assist удалён.
Опция «удалённое администрирование» включает RDP с NLA только с указанных адресов.

### 4.12 Шифрование дисков

Автоматическое шифрование устройства запрещено. Опция «BitLocker для ноутбуков» должна сопровождаться
обязательным сохранением ключа восстановления в указанное место (файл на USB, печать) до перезагрузки,
иначе не активироваться.

## 5. Нефункциональные требования

- Встроенный валидатор перед выгрузкой файла. Проверки, каждая из которых иначе приводит к остановке установки
  с кодом 0x80220005 (подтверждено логом сбоя от 13.09.2026): длина каждого элемента Path не более 259 символов;
  отсутствие XML-комментариев внутри компонентов; каждая синхронная команда завершается кодом 0;
  имена, группы и порядок элементов учётных записей по документации Microsoft; языки ввода только в формате
  «LCID:раскладка» (языки без LCID, как ru-UA, только через скрипт после входа).
- Один файл `autounattend.xml` не больше 1 МБ, кодировка UTF-8, валидный XML, проходит на Windows 11 24H2 и новее.
- Только PowerShell 5.1 и встроенные модули; никаких модулей из галереи.
- Идемпотентность: повторный запуск любого скрипта безопасен.
- Логи в `C:\ProgramData\Unattend\Logs` с уровнями OK/WARN/ERROR; конструктор умеет их прочитать и показать сводку.
- Документ «как отключить» на каждую настройку (одна команда или один ключ реестра).
- Проверка перед выпуском: автоматический тест в виртуальной машине по чек-листу из README.

## 6. Открытые вопросы к заказчику

1. Стыковка с проектом пользователей: чем и когда он запускается после установки, нужна ли ему точка входа в Post-OOBE.
2. Общие папки: нужны ли они между ПК группы? Тогда после назначения паролей тем проектом понадобятся правила брандмауэра.
3. NetBIOS: можно ли выключать, есть ли старые устройства (принтеры, NAS), которые ищутся по имени?
4. Удалённое администрирование: как свой админ будет обслуживать ПК (RDP, AnyDesk, лично)?
5. Токены ЭЦП и банковские клиенты: какие используются, чтобы проверить их со строгими правилами ASR.
6. Программы учёта (1С, M.E.Doc и подобные): пишут ли в Документы, чтобы решить про контролируемый доступ к папкам.
7. Нужны ли новый Outlook, Phone Link, Teams кому-то из сотрудников.
8. Ноутбуки: включать ли BitLocker с сохранением ключа.
9. Отсрочка обновлений функций: 90 дней устраивает?
10. Обход TPM: есть ли в парке ПК без TPM 2.0, или обход можно убрать.

## 7. Этапы

1. v0.1 (готово): базовый файл, разбор оригинала, этот черновик.
2. v0.2: пункты заказчика, проверка в виртуальной машине, исправления.
3. v0.3: профили (офис, бухгалтерия, ноутбук) как готовые блоки `$Config`.
4. v1.0 конструктор: предлагается автономная веб-страница (HTML и JavaScript без сервера), которая работает
   с локального диска, хранит профили в JSON и собирает XML в браузере. Плюсы: не требует установки,
   не требует прав, работает на любом ПК, легко проверяется. Альтернатива: PowerShell с WPF-окном.
