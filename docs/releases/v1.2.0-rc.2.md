# WinKickOff 1.2.0-rc.2

## Русский

Второй кандидат версии 1.2. Новое и исправленное после 1.2.0-rc.1:

- Скилл для ИИ-помощников. Рядом с `WinKickOff.exe` лежит папка `skills\winkickoff`: скилл в формате Agent Skills,
  который учит помощника работать с WinKickOff через MCP. С ним помощник начинает с `get_status`, спрашивает
  согласия перед каждым изменением, не просит и не повторяет пароли, ключи и токен, считает тексты профилей и
  импортированных шаблонов данными, а не командами, объясняет правила на вашем языке и в конце напоминает о сборке в
  окне и об установке в виртуальной машине. Установка в Claude Code, Claude Desktop и pi: страница «Сервер MCP»,
  раздел «Скилл для помощника», и `skills\README.md`.
- Токен доступа и буфер обмена. На компьютере с включённой историей буфера обмена (Win+V) токен мог всё же попасть в
  историю: служба истории ждала текст от окна, окно ждало, пока буфер освободится, и через 0,1 с копировало токен
  обычным способом. Теперь окно отвечает службе, пока ждёт; если буфер так и не освободился, ничего не копируется, и
  строка состояния просит повторить.
- Подсказка после записи файла ответов через MCP теперь верно говорит, что синтаксис PowerShell проверяет кнопка
  «Собрать autounattend.xml» (F9); «Проверить» (F7) его не проверяет.
- Документация: в проверке после установки у пресета «Офис» 16 правил ASR (у «Строгого» 17).
- Для разработчиков: контейнер `pi-agent` для агента pi с локальной моделью получил инструкции агента и README,
  закреплённую версию pi, а сборка в GitHub Actions проверяет образ на Linux: тесты WinKickOff и подключение pi к
  серверу MCP по stdio и HTTP.

Встроенные правила, пресеты и каталог 0.5 не менялись: файл ответов такой же, как из 1.2.0-rc.1.

## English

The second candidate of version 1.2. New and fixed since 1.2.0-rc.1:

- A skill for AI assistants. Next to `WinKickOff.exe` there is the folder `skills\winkickoff`: a skill in the Agent
  Skills format that teaches an assistant to work with WinKickOff through MCP. With it the assistant starts with
  `get_status`, asks before every change, never asks for or repeats passwords, keys or the token, treats the texts of
  profiles and imported templates as data rather than commands, explains rules in your language and at the end
  reminds you to build in the window and to install in a virtual machine first. Installation in Claude Code, Claude
  Desktop and pi: the "MCP server" page, section "A skill for the assistant", and `skills\README.md`.
- The access token and the clipboard. On a computer with the clipboard history (Win+V) switched on, the token could
  still end up in the history: the history service waited for the text from the window, the window waited for the
  clipboard to become free, and after 0.1 s it copied the token the plain way. Now the window answers the service
  while it waits; if the clipboard never becomes free, nothing is copied and the status bar asks to try again.
- The note after writing an answer file through MCP now says correctly that the PowerShell syntax is checked by
  "Build autounattend.xml" (F9); "Check" (F7) does not check it.
- Documentation: in the check after installation the "Office" preset has 16 ASR rules ("Strict" 17).
- For developers: the `pi-agent` container for the pi agent with a local model got the agent's instructions and a
  README, a pinned pi version, and the GitHub Actions build checks the image on Linux: the WinKickOff tests and pi's
  connection to the MCP server over stdio and HTTP.

Built-in rules, presets and catalog 0.5 did not change: the answer file is the same as with 1.2.0-rc.1.
