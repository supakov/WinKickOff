# WinKickOff 1.4.0-rc.11

## Русский

Одиннадцатый кандидат версии 1.4, собран из ветки `unattend-tree` (план `docs/reports/2026-10-13-plan-unattend.md`,
этап 5) для приёмки в виртуальной машине. Изменения после 1.4.0-rc.10:

- Каталог 0.11: новое действие правил `xml-setting` записывает любую штатную настройку файла ответов (проход,
  компонент, путь элементов, значение) там, где реестр при установке не работает. Настройки одного компонента и
  прохода собираются в один элемент для обеих архитектур.
- Два новых правила, выключены по умолчанию, в корне «autounattend.xml»: «Без Dynamic Update при установке»
  (установщик не скачивает обновления себя, драйверов и образа из Windows Update) и «Без диагностических данных
  установщика Windows».
- Приёмка в ВМ: установка с обоими правилами; `setupact.log` без загрузки Dynamic Update.

## Українська

Одинадцятий кандидат версії 1.4, зібраний із гілки `unattend-tree` (план `docs/reports/2026-10-13-plan-unattend.md`,
етап 5) для приймання у віртуальній машині. Зміни після 1.4.0-rc.10:

- Каталог 0.11: нова дія правил `xml-setting` записує будь-яке штатне налаштування файлу відповідей (прохід,
  компонент, шлях елементів, значення) там, де реєстр під час інсталяції не працює. Налаштування одного компонента і
  проходу збираються в один елемент для обох архітектур.
- Два нові правила, вимкнені за замовчуванням, у корені «autounattend.xml»: «Без Dynamic Update під час інсталяції»
  (інсталятор не завантажує оновлення себе, драйверів і образу з Windows Update) та «Без діагностичних даних
  інсталятора Windows».
- Приймання у ВМ: інсталяція з обома правилами; `setupact.log` без завантаження Dynamic Update.

## English

The eleventh candidate of version 1.4, built from the branch `unattend-tree` (plan `docs/reports/2026-10-13-plan-unattend.md`,
stage 5) for the acceptance in a virtual machine. Changes after 1.4.0-rc.10:

- Catalog 0.11: the new rule action `xml-setting` writes any native setting of the answer file (pass, component,
  element path, value) where the registry cannot act during installation. The settings of one component and pass
  merge into one element for both architectures.
- Two new rules, off by default, in the root "autounattend.xml": "No Dynamic Update during installation" (Setup does
  not download updates of itself, of drivers and of the image from Windows Update) and "No diagnostic data from
  Windows Setup".
- Acceptance in a VM: an installation with both rules on; `setupact.log` without a Dynamic Update download.
