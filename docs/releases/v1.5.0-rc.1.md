# WinKickOff 1.5.0-rc.1

## Русский

Первый кандидат версии 1.5: ветка `unattend-tree` (план `docs/reports/2026-10-13-plan-unattend.md`, все семь этапов,
кандидаты 1.4.0-rc.9 по rc.12) влита в `main`. Изменения после 1.4.0-rc.8, в одном списке:

- Дерево правил по механизму: три корня «Установка» (настройки autounattend.xml и сценарии установки), «Штатные
  политики» (встроенные правила под ключами Policies и импортированные шаблоны) и «Прочее» (остальные значения реестра,
  службы, приложения). Тематические разделы под корнем большинства своих правил, правила другого механизма в зеркале
  раздела под нужным корнем; идентификаторы правил не менялись, профили и пресеты открываются как раньше. Разделы из
  одного-двух правил растворены в родительском; корни раскрыты при старте.
- Панель справа: редактор параметров, кнопки раздела и кнопки импорта над описанием, с прокруткой; длинные заголовки
  импортированных шаблонов обрезаны с подсказкой целиком, списки выбирают по позиции, подписи параметров переносятся.
- Формы «Установка» и «Учётные записи» прокручиваются; Tab приводит поле в видимую область. В виде раздела под его
  кнопками рамка «Этот ПК» повторяет команды контекстного меню для выделения.
- Каталог 0.9: правила «Без автоматической активации», «Автоматический вход без пароля» (учётная запись из профиля,
  без пароля) и «Контакты поддержки» (OEMInformation), все выключены по умолчанию.
- Каталог 0.11: действие `xml-setting` для любой настройки файла ответов; первые правила «Без Dynamic Update» и
  «Без диагностики установщика», выключены по умолчанию.
- Профиль формата 5: форма «Установка» с полем «Рабочая группа» и блоком «Диск» (установщик спрашивает, куда
  устанавливать, или установка в указанный раздел без вопроса; разметка диска не делается).
- Правило «Драйверы из папки Drivers установочного носителя» (выключено по умолчанию): пакеты `.inf` из папки
  `Drivers` рядом с autounattend.xml ставятся через pnputil при первой перезагрузке.
- Чтение этого ПК после чтения 14.10.2026: правило, которое удаляет значение и затем записывает его
  (`defender.realtime`), больше не проверяет удаление, поэтому читается как действующее вместе с четырьмя политиками
  Defender, которые оно покрывает; значения чистой Windows под Policies (TCGSecurityActivationDisabled 0,
  NC_PersonalFirewallConfig 0) не считаются доказательством политики; правила профиля по умолчанию, которые у
  текущего пользователя отличаются (Windows меняет его профиль после первого входа), остаются как в открытом профиле
  с сообщением в списке.
- Приёмка в ВМ: пункты кандидатов 1.4.0-rc.9 по rc.12 (активация, автоматический вход, контакты поддержки, Dynamic
  Update, рабочая группа, установка в раздел, драйверы из папки Drivers) и чтение этого ПК после установки.

## Українська

Перший кандидат версії 1.5: гілка `unattend-tree` (план `docs/reports/2026-10-13-plan-unattend.md`, усі сім етапів,
кандидати 1.4.0-rc.9 по rc.12) влита в `main`. Зміни після 1.4.0-rc.8, одним списком:

- Дерево правил за механізмом: три корені «Інсталяція» (налаштування autounattend.xml і сценарії інсталяції),
  «Штатні політики» (вбудовані правила під ключами Policies та імпортовані шаблони) і «Інше» (решта значень реєстру,
  служби, застосунки). Тематичні розділи під коренем більшості своїх правил, правила іншого механізму в дзеркалі
  розділу під потрібним коренем; ідентифікатори правил не змінювалися, профілі та пресети відкриваються як раніше.
  Розділи з одного-двох правил розчинені в батьківському; корені розкриті під час старту.
- Панель праворуч: редактор параметрів, кнопки розділу і кнопки імпорту над описом, із прокручуванням; довгі
  заголовки імпортованих шаблонів обрізані з підказкою повністю, списки вибирають за позицією, підписи параметрів
  переносяться.
- Форми «Інсталяція» і «Облікові записи» прокручуються; Tab приводить поле у видиму область. У вигляді розділу під
  його кнопками рамка «Цей ПК» повторює команди контекстного меню для виділення.
- Каталог 0.9: правила «Без автоматичної активації», «Автоматичний вхід без пароля» (обліковий запис із профілю, без
  пароля) і «Контакти підтримки» (OEMInformation), усі вимкнені за замовчуванням.
- Каталог 0.11: дія `xml-setting` для будь-якого налаштування файлу відповідей; перші правила «Без Dynamic Update» і
  «Без діагностики інсталятора», вимкнені за замовчуванням.
- Профіль формату 5: форма «Інсталяція» з полем «Робоча група» і блоком «Диск» (інсталятор запитує, куди
  встановлювати, або інсталяція у вказаний розділ без запитання; розмітка диска не виконується).
- Правило «Драйвери з папки Drivers інсталяційного носія» (вимкнене за замовчуванням): пакети `.inf` з папки
  `Drivers` поруч з autounattend.xml ставляться через pnputil під час першого перезавантаження.
- Читання цього ПК після читання 14.10.2026: правило, яке видаляє значення і потім записує його
  (`defender.realtime`), більше не перевіряє видалення, тому читається як чинне разом із чотирма політиками Defender,
  які воно покриває; значення чистої Windows під Policies (TCGSecurityActivationDisabled 0,
  NC_PersonalFirewallConfig 0) не вважаються доказом політики; правила профілю за замовчуванням, які в поточного
  користувача відрізняються (Windows змінює його профіль після першого входу), залишаються як у відкритому профілі з
  повідомленням у списку.
- Приймання у ВМ: пункти кандидатів 1.4.0-rc.9 по rc.12 (активація, автоматичний вхід, контакти підтримки, Dynamic
  Update, робоча група, інсталяція в розділ, драйвери з папки Drivers) і читання цього ПК після інсталяції.

## English

The first candidate of version 1.5: the branch `unattend-tree` (plan `docs/reports/2026-10-13-plan-unattend.md`, all
seven stages, candidates 1.4.0-rc.9 to rc.12) merged into `main`. Changes after 1.4.0-rc.8, in one list:

- The rule tree by mechanism: three roots "Installation" (settings of autounattend.xml and the installation scripts),
  "Standard policies" (built-in rules under Policies keys and imported templates) and "Other" (the other registry
  values, services, apps). A thematic group sits under the root of most of its rules, a rule of another mechanism in a
  mirror of its group under the right root; rule ids are unchanged, profiles and presets open as before. Groups of one
  or two rules were dissolved into their parents; the roots start open.
- The right panel: the parameter editor, the group buttons and the import buttons above the description, with a
  scroll bar; long titles of imported templates are cut with a tip that shows the whole, lists choose by position,
  parameter labels wrap.
- The forms "Installation" and "Accounts" scroll; Tab brings the field into view. The group view repeats the commands
  of the context menu for the selection in a frame "This PC" under its buttons.
- Catalog 0.9: the rules "Automatic activation off", "Automatic sign-in without a password" (an account of the
  profile, without a password) and "Support contacts" (OEMInformation), all off by default.
- Catalog 0.11: the action `xml-setting` for any setting of the answer file; the first rules "Dynamic Update off" and
  "Setup diagnostics off", off by default.
- Profile format 5: the form "Installation" with the field "Workgroup" and the block "Disk" (Windows Setup asks where
  to install, or the installation into the given partition without a question; the disk is not repartitioned).
- The rule "Drivers from the Drivers folder of the installation media" (off by default): the `.inf` packages of the
  folder `Drivers` next to autounattend.xml are installed with pnputil at the first restart.
- The read of this PC after the read of 14.10.2026: a rule that removes a value and then writes it
  (`defender.realtime`) no longer checks the removal, so it reads as in effect together with the four Defender
  policies it covers; the values of a clean Windows under Policies (TCGSecurityActivationDisabled 0,
  NC_PersonalFirewallConfig 0) are no evidence of a policy; default-user rules that differ for the current user
  (Windows changes that profile after the first sign-in) stay as in the open profile, with a line in the message list.
- Acceptance in a VM: the items of the candidates 1.4.0-rc.9 to rc.12 (activation, automatic sign-in, support
  contacts, Dynamic Update, the workgroup, the installation into a partition, drivers from the Drivers folder) and the
  read of this PC after the installation.
