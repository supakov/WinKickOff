# WinKickOff 1.2.0-rc.1

## Русский

Первый кандидат версии 1.2. Новое: сервер MCP (Model Context Protocol), через который ИИ-клиенты (Claude Code,
Claude Desktop и другие) читают каталог правил и открытый профиль, а с разрешения пользователя изменяют профиль
и создают файлы.

- Два транспорта: HTTP только на этом компьютере (127.0.0.1) и stdio (клиент запускает WinKickOff как дочерний
  процесс без окна). В портабельной сборке для stdio есть второй файл `WinKickOff-mcp.exe`.
- По умолчанию только чтение. Режим «чтение и изменение открытого профиля» и режим «изменение и создание файлов»
  включаются только пользователем в меню «MCP» и действуют до закрытия окна. Через MCP никогда не выполняются
  применение к этому ПК, проверки PowerShell, удаление или замена файлов, импорт шаблонов, изменение настроек.
- Пароли и ключи продукта не возвращаются ни одним инструментом: профиль отдаётся с пометками «есть пароль»,
  предпросмотр файла ответов собирается из копии без секретов.
- Меню «MCP»: запуск и остановка сервера, режим, монитор запросов (время, клиент, инструмент, аргументы без
  свободного текста, результат), копирование конфигурации клиента, новый токен доступа, автозапуск (только чтение).
- Доступ по HTTP защищён токеном, который программа создаёт сама и хранит в `settings.json`; проверяются
  заголовки Host и Origin, соединения принимаются только с этого компьютера.
- Все изменения агента видны в окне как несохранённые; сохраняет пользователь. Файл ответов, записанный через MCP,
  не проходил проверку синтаксиса PowerShell: проверьте его в окне.
- Документация: страница «Сервер MCP» в документации пользователя, техническое описание в `docs/technical/editor`.

Встроенные правила, пресеты и каталог 0.5 не менялись: файл ответов такой же, как из 1.1.0-rc.4.

## Українська

Перший кандидат версії 1.2. Нове: сервер MCP (Model Context Protocol), через який ШІ-клієнти (Claude Code,
Claude Desktop та інші) читають каталог правил і відкритий профіль, а з дозволу користувача змінюють профіль і
створюють файли.

- Два транспорти: HTTP лише на цьому комп'ютері (127.0.0.1) і stdio (клієнт запускає WinKickOff як дочірній
  процес без вікна). У портабельній збірці для stdio є другий файл `WinKickOff-mcp.exe`.
- За замовчуванням лише читання. Режим «читання і зміна відкритого профілю» та режим «зміна і створення файлів»
  вмикає лише користувач у меню «MCP», і вони діють до закриття вікна. Через MCP ніколи не виконуються
  застосування до цього ПК, перевірки PowerShell, видалення чи заміна файлів, імпорт шаблонів, зміна налаштувань.
- Паролі й ключі продукту не повертає жоден інструмент: профіль віддається з позначками «є пароль», попередній
  перегляд файлу відповідей збирається з копії без секретів.
- Меню «MCP»: запуск і зупинка сервера, режим, монітор запитів (час, клієнт, інструмент, аргументи без вільного
  тексту, результат), копіювання конфігурації клієнта, новий токен доступу, автозапуск (лише читання).
- Доступ по HTTP захищено токеном, який програма створює сама і зберігає в `settings.json`; перевіряються
  заголовки Host і Origin, з'єднання приймаються лише з цього комп'ютера.
- Усі зміни агента видно у вікні як незбережені; зберігає користувач. Файл відповідей, записаний через MCP, не
  проходив перевірку синтаксису PowerShell: перевірте його у вікні.
- Документація: сторінка «Сервер MCP» у документації користувача, технічний опис у `docs/technical/editor`.

Вбудовані правила, пресети й каталог 0.5 не змінювалися: файл відповідей такий самий, як із 1.1.0-rc.4.

## English

The first candidate of version 1.2. New: an MCP server (Model Context Protocol) through which AI clients (Claude
Code, Claude Desktop and others) read the rule catalog and the open profile and, with the user's permission, change
the profile and create files.

- Two transports: HTTP on this computer only (127.0.0.1) and stdio (the client starts WinKickOff as a child process
  without a window). The portable build ships a second file `WinKickOff-mcp.exe` for stdio.
- Read-only by default. The modes "read and change the open profile" and "change and create files" are switched
  on only by the user in the "MCP" menu and last until the window closes. Applying to this PC, PowerShell checks,
  deleting or replacing files, importing templates and changing settings never happen through MCP.
- Passwords and product keys are returned by no tool: the profile comes with "has password" marks and the preview
  of the answer file is built from a copy without secrets.
- The "MCP" menu: start and stop the server, the mode, the request monitor (time, client, tool, arguments without
  free text, result), copying the client configuration, a new access token, autostart (read only).
- HTTP access is protected by a token the program generates and keeps in `settings.json`; the Host and Origin
  headers are checked and connections are accepted from this computer only.
- Every change made by an agent shows in the window as an unsaved change; the user saves. An answer file written
  through MCP skipped the PowerShell syntax check: check it in the window.
- Documentation: the "MCP server" page of the user documentation and a technical description in
  `docs/technical/editor`.

Built-in rules, presets and catalog 0.5 did not change: the answer file is the same as with 1.1.0-rc.4.
