# WinKickOff 1.3.0-rc.1

## Русский

Первый кандидат версии 1.3. Изменения после 1.2.0-rc.4:

- Каталог правил хранится в JSON вместо TOML. Для пользователя ничего не меняется: четыре пресета и профиль со всеми
  включёнными правилами собирают те же файлы ответов и скрипты байт в байт, версия каталога осталась 0.6. Файлы
  каталога читаются строго: незнакомое поле (например, с опечаткой в имени) и значение неверного типа теперь ошибки
  каталога, а не молча пропущенное или преобразованное значение; повтор ключа и null тоже ошибки. Файл перевода
  каталога с ошибкой не загружается: окно и сервер MCP показывают тексты правил по-английски. Переводчики правят
  тексты правил в `rules/lang/ru.json` и `rules/lang/uk.json`.
- Файлы каталога в меню «ADMX». «Экспортировать импортированные шаблоны» сохраняет выбранный импорт в один файл JSON
  (путь исходной папки на этом компьютере в него не пишется). «Импортировать файл каталога...» загружает такой файл
  (тип «Каталог WinKickOff»: `.json`, а также сжатые `.json.gz` и `.json.xz`) на другом компьютере, где самих шаблонов
  нет. Файл читается и проверяется в фоне, окно при этом не зависает. При повторном импорте того же файла программа
  спрашивает: «Да» обновляет прежний импорт (его ветка и выбор в профилях сохраняются), «Нет» добавляет ещё одну ветку,
  «Отмена» ничего не импортирует. Импорт и экспорт выполняются только в окне, через MCP они недоступны.
- «Импортировать каталог программы»: каталоги шаблонов, которые поставляются вместе с программой; повторный импорт
  обновляет ту же ветку и сохраняет имя, которое ей дал пользователь. Механизм готов, но ни один каталог пока не
  поставляется: шаблоны Microsoft войдут в программу только после проверки лицензии, поэтому пункт меню пока
  недоступен.
- Если одна и та же политика есть в двух импортах, правило и его значения реестра берутся из самого надёжного источника:
  каталог программы, затем шаблоны этой Windows, затем папка с шаблонами, затем файл каталога (внутри одного вида в
  порядке веток). До 1.3 побеждал импорт, загруженный первым. Другие ветки показывают политику с той же галочкой,
  порядок веток не меняется. Политика, правило которой заняло бы место правила другого импорта (например, политика «Off»
  рядом с политикой, у которой есть отдельное правило для состояния «Отключено»), не загружается и не показывается
  вместо него. В 1.2 правила двух политик одного импорта с одинаковым идентификатором (в шаблонах Windows такого нет)
  нумеровались по названию на языке интерфейса, теперь по английскому названию, поэтому выбор в профиле не зависит от
  языка.
- Профиль помнит, в каком виде источника выбрана политика (или в самом надёжном виде, из которого она потом
  действовала). Если политика, выбранная, например, в шаблонах этой Windows, теперь есть только в файле каталога (те
  шаблоны скрыты или удалены), выбор не переходит на файл каталога молча: при открытии профиля появляется
  предупреждение, выбор остаётся в ветке «Неизвестные правила и политики» и возвращается, когда те шаблоны снова
  показаны. Так значения реестра из менее надёжного файла не применяются вместо проверенных. Выбор в профиле,
  сохранённом до 1.3, считается сделанным в шаблонах из папки (файлов каталога тогда не было), поэтому и он не уходит в
  файл каталога без предупреждения. Описание такого выбора в окне объясняет, почему он отложен, и предлагает
  показать снова или импортировать только шаблоны того же или более надёжного вида; предупреждение видно в списке
  сообщений внизу окна при запуске программы и после того, как окно перестроилось (ветка скрыта, импортирован файл
  каталога).
- Файл каталога, как и файлы шаблонов, считается недоверенным: файл больше 64 МБ (в том числе после распаковки) или с
  более чем миллионом значений не читается, каждая запись проверяется (только известные поля, безопасные разделы,
  имена и значения реестра, допустимые диапазоны чисел, ограничения размера), и при ошибке файл не импортируется.
  Раздел реестра не может содержать пустую часть, «.» или «..», а имя и значение не могут содержать управляющие
  символы и символы, недопустимые в XML. Так же при каждой загрузке проверяются импорты, сохранённые в папке `admx`
  программы: импорт с повреждённым файлом (например, не строгий JSON или слишком большой) или с идентификатором в
  `import.json`, который не совпадает с именем папки, не загружается, и окно сообщает об этом, а отдельные
  неподходящие политики в нём только пропускаются (следующий пункт). Умышленно составленный текст в файле каталога
  больше не может надолго задержать запуск программы.
- Необычная или повреждённая политика в папке шаблонов больше не останавливает импорт: она пропускается (входит в
  число «пропущено»), остальные политики импортируются. Так же загружаются импорты, сохранённые версией 1.2: проверка
  при загрузке пропускает в них только такие политики. Файл каталога с такой политикой не импортируется вовсе.
- Группа «Проводник и рабочий стол» (прежде «Проводник: «Этот компьютер» и область навигации») разделена на «Папки в
  «Этот компьютер»», «Область навигации» и «Значки рабочего стола» и получила 26 новых правил: «Корзина» и «Панель
  управления» в «Этот компьютер»; показ или скрытие пунктов области навигации («Библиотеки», «Сеть», «Корзина»,
  «Панель управления», папка пользователя, «Linux», USB-накопители, все папки, облачные файлы в «Главной»); значки на
  рабочем столе. Все новые правила выключены по умолчанию, прежние правила группы сохранили свои идентификаторы.
  Проверяйте их в виртуальной машине: часть известна только из сторонних источников (карточка 20 справочника).
- Меню «Этот ПК»: «Применить выбранное сейчас...» и «Вернуть выбранное к умолчаниям Windows сейчас...» для выключенных
  правил «Объемные объекты», «Корзина» и «Панель управления» в «Этот компьютер» записывают `HiddenByDefault` = 1, как
  для остальных папок «Этот компьютер», и тем скрывают эти пункты; раньше их возвращали только вручную. Разделы реестра
  не удаляются: если раздела не было, он создаётся со значением 1. Что Windows скрывает эти три пункта по этому
  значению, ещё нужно проверить в виртуальной машине.
- Учётная запись при установке: в форме «Учётные записи» есть режим «Спросить учётную запись при установке». Тогда
  учётные записи и пароли не пишутся в файл, установщик Windows спрашивает имя одной учётной записи, и она становится
  администратором; обычную учётную запись для работы нужно добавить после установки. Учётные записи формы остаются в
  профиле. Проверка предупреждает, если выключены правила, без которых установщик потребует аккаунт Microsoft или
  остановится на экране сети. Профили сохраняются в формате 3.
- Редакция при установке: режим ключа «Выбрать редакцию при установке» (прежде «Спросить ключ и редакцию во время
  установки») показывает страницу ключа продукта, а «У меня нет ключа продукта» открывает список редакций. Поле
  редакции в форме «Установка» доступно только для универсального ключа. Проверка напоминает, что защита WinKickOff
  рассчитана на Pro: в Домашней не работают отложенные обновления компонентов и BitLocker, часть политик Copilot и
  Recall не поддерживается.
- Список редакций для универсального ключа расширен: Pro N, Pro for Workstations и Pro for Workstations N, Pro
  Education и Pro Education N, Education N, Enterprise N, Enterprise G и Enterprise G N, Enterprise LTSC и Enterprise
  N LTSC. Кроме Pro и Education, ключи списка являются ключами клиента KMS (GVLK) из таблицы Microsoft: такая Windows
  активируется сервером KMS организации, а без него после установки нужно ввести ключ лицензии. Выбранная редакция
  должна быть на установочном носителе; форма «Установка» напоминает об этом под списком.
- Правило «Клавиши переключения языка ввода и раскладки клавиатуры» (`default-user.input-switch-keys`, выключено по
  умолчанию): левый Alt+Shift, Ctrl+Shift или без клавиш, отдельно для языка и для раскладки, для учётных записей,
  созданных при установке и после неё, и для экрана входа. Win+Пробел работает всегда. Проверка не даёт назначить
  языку и раскладке одинаковые клавиши. Меню «Этот ПК» это правило к работающему компьютеру не применяет.
- Безопасность: параметры правил подставляются только в записываемые значения, никогда в раздел реестра или имя
  значения, а путь профиля пользователя по умолчанию пишется в одинарных кавычках. Раньше импортированный шаблон с
  умышленно составленными полями мог внедрить команду PowerShell в файл ответов, и она выполнилась бы при установке от
  имени SYSTEM, если включить такую политику. Файлы ответов прежних сборок открываются как раньше.
- Постоянные текстовые значения импортированных политик пишутся как есть: фигурные скобки в них (например,
  `https://example.com/{id}`) остаются текстом, а не считаются параметром правила. Если сборка всё же не удалась,
  «Проверить» и «Собрать autounattend.xml» показывают ошибку «Сборка невозможна: ...» в списке проблем, а сервер MCP
  возвращает её как ошибку сборки.
- Имя и автор профиля хранятся одной строкой (переводы строк становятся пробелами), а в скриптах меню «Этот ПК» имя
  профиля всегда остаётся в строке комментария. Раньше имя присланного профиля с переводом строки могло добавить в
  такой скрипт команду, которая выполнилась бы с правами администратора.
- Профиль неверной формы открывается: поле не того типа (например, список вместо объекта или текст вместо числа)
  получает значение по умолчанию, обычно с предупреждением, а остальные настройки загружаются. Файл, который не
  является объектом JSON, не открывается, и программа называет причину. Профиль читается так же строго, как файлы
  каталога: с повтором ключа или с вложенностью глубже 32 уровней он не открывается, в том числе внутри файла ответов,
  а файл профиля больше 16 МБ не читается.
- Сохранение профиля больше не может оставить пустой или недописанный файл: профиль пишется во временный файл, который
  затем заменяет прежний. Половина символа, которая остаётся в поле ввода, если эмодзи стёрт не полностью, сохраняется
  как знак замены (U+FFFD); раньше файл профиля в этом случае оказывался пустым. «Проверить» называет поле с такой
  половиной символа, и файл ответов не собирается, пока текст не исправлен.
- Сервер MCP: `set_param` больше не записывает true или false в параметр с вариантами 0 и 1 (ошибка
  `invalid_arguments`), а такое значение в профиле, сохранённом через MCP версии 1.2, при открытии становится
  вариантом 0 или 1, которому оно равно. `get_profile` показывает у импортированной политики поле `source` (вид
  источника выбора), а отложенные выборы находятся в `unknown`.
- Скрипты первого входа пользователя и после первичной настройки умеют записывать и удалять значения реестра (среда
  выполнения 0.6); это нужно новым правилам области навигации.
- Ветка «Неизвестные правила и политики» в конце дерева: если в профиле есть выбор для правил, которых нет в
  загруженном каталоге (политики скрытых или удалённых импортов, правила другой версии WinKickOff), окно показывает их
  там с сохранённым состоянием и параметрами. Описание называет сохранённый скрытый импорт, где есть политика, и
  предлагает показать его снова; если такого импорта нет, кнопки предлагают импортировать шаблоны того вида, из
  которого выбор вернётся.
  Такие записи не попадают в файл ответов и не применяются.
- Окно больше не выводит сообщение Tcl, если его закрыть сразу после ввода в поиск.
- Контейнер `pi-agent` (помощник с локальной моделью): pi снова работает со своими настройками по умолчанию и режимом
  codemode, без обёртки 1.2.0-rc.3 и 1.2.0-rc.4, которая отключала его инструменты и заменяла системные инструкции;
  образ ставит pi 1.0.0 вместо 0.99.2. Образ нужно пересобрать (`pi-agent/README.md`).

Совместимость: профили и файлы ответов версии 1.2 открываются как прежде (профиль формата 2 открывается в режиме
«Создать эти учётные записи»). Переход каталога на JSON не изменил результат: четыре пресета собирают те же файлы
ответов, что и до перехода. По сравнению с 1.2.0-rc.4 в пресетах появились 27 новых правил каталога 0.6, и во всех
четырёх пресетах они выключены; действия прежних правил не менялись, а текст скриптов в файле ответов отличается
(функции реестра в скриптах первого входа и после первичной настройки, путь профиля по умолчанию в одинарных кавычках).
Профиль, сохранённый в 1.3 (формат 3), версия 1.2 откроет с предупреждением о формате и без режима «Спросить учётную
запись при установке».

## Українська

Перший кандидат версії 1.3. Зміни після 1.2.0-rc.4:

- Каталог правил зберігається в JSON замість TOML. Для користувача нічого не змінюється: чотири пресети й профіль з
  усіма ввімкненими правилами збирають ті самі файли відповідей і скрипти байт у байт, версія каталогу залишилася 0.6.
  Файли каталогу читаються суворо: незнайоме поле (наприклад, з помилкою в назві) і значення неправильного типу тепер є
  помилками каталогу, а не мовчки пропущеним чи перетвореним значенням; повтор ключа й null теж є помилками. Файл
  перекладу каталогу з помилкою не завантажується: вікно й сервер MCP показують тексти правил англійською.
  Перекладачі правлять тексти правил у `rules/lang/ru.json` і `rules/lang/uk.json`.
- Файли каталогу в меню «ADMX». «Експортувати імпортовані шаблони» зберігає вибраний імпорт в один файл JSON (шлях
  вихідної папки на цьому комп'ютері в нього не записується). «Імпортувати файл каталогу...» завантажує такий файл
  (тип «Каталог WinKickOff»: `.json`, а також стиснуті `.json.gz` і `.json.xz`) на іншому комп'ютері, де самих шаблонів
  немає. Файл читається й перевіряється у фоні, вікно при цьому не зависає. Під час повторного імпорту того самого
  файлу програма запитує: «Так» оновлює попередній імпорт (його гілка й вибір у профілях зберігаються), «Ні» додає ще
  одну гілку, «Скасувати» нічого не імпортує. Імпорт і експорт виконуються лише у вікні, через MCP вони недоступні.
- «Імпортувати каталог програми»: каталоги шаблонів, які постачаються разом із програмою; повторний імпорт оновлює ту
  саму гілку й зберігає назву, яку їй дав користувач. Механізм готовий, але жоден каталог поки не постачається:
  шаблони Microsoft увійдуть до програми лише після перевірки ліцензії, тому пункт меню поки недоступний.
- Якщо та сама політика є у двох імпортах, правило і його значення реєстру беруться з найнадійнішого джерела: каталог
  програми, потім шаблони цієї Windows, потім папка із шаблонами, потім файл каталогу (усередині одного виду в порядку
  гілок). До 1.3 перемагав імпорт, завантажений першим. Інші гілки показують політику з тією самою позначкою, порядок
  гілок не змінюється. Політика, правило якої зайняло б місце правила іншого імпорту (наприклад, політика «Off» поруч із
  політикою, що має окреме правило для стану «Вимкнено»), не завантажується й не показується замість нього. У 1.2
  правила двох політик одного імпорту з однаковим ідентифікатором (у шаблонах Windows такого немає) нумерувалися за
  назвою мовою інтерфейсу, тепер за англійською назвою, тому вибір у профілі не залежить від мови.
- Профіль пам'ятає, в якому виді джерела вибрано політику (або в найнадійнішому виді, з якого вона потім діяла).
  Якщо політика, вибрана, наприклад, у шаблонах цієї Windows, тепер є лише у файлі каталогу (ті шаблони приховано або
  видалено), вибір не переходить на файл каталогу мовчки: під час відкриття профілю з'являється попередження, вибір
  залишається в гілці «Невідомі правила та політики» й повертається, коли ті шаблони знову показано. Так значення
  реєстру з менш надійного файлу не застосовуються замість перевірених. Вибір у профілі, збереженому до 1.3,
  вважається зробленим у шаблонах з папки (файлів каталогу тоді не було), тому й він не переходить на файл каталогу
  без попередження. Опис такого вибору у вікні пояснює, чому його відкладено, і пропонує знову показати або
  імпортувати лише шаблони того самого або надійнішого виду; попередження видно в списку повідомлень унизу вікна під
  час запуску програми й після того, як вікно перебудувалося (гілку приховано, імпортовано файл каталогу).
- Файл каталогу, як і файли шаблонів, вважається недовіреним: файл, більший за 64 МБ (зокрема після розпакування) або
  з понад мільйоном значень, не читається, кожен запис перевіряється (лише відомі поля, безпечні розділи, імена й
  значення реєстру, допустимі діапазони чисел, обмеження розміру), і в разі помилки файл не імпортується. Розділ
  реєстру не може містити порожню частину, «.» або «..», а ім'я й значення не можуть містити керівні символи та
  символи, неприпустимі в XML. Так само під час кожного завантаження перевіряються імпорти, збережені в папці `admx`
  програми: імпорт із пошкодженим файлом (наприклад, не суворий JSON або завеликий) або з ідентифікатором в
  `import.json`, який не збігається з назвою папки, не завантажується, і вікно про це повідомляє, а окремі непридатні
  політики в ньому лише пропускаються (наступний пункт). Зловмисно складений текст у файлі каталогу більше не може
  надовго затримати запуск програми.
- Незвична або пошкоджена політика в папці шаблонів більше не зупиняє імпорт: вона пропускається (входить до числа
  «пропущено»), решта політик імпортується. Так само завантажуються імпорти, збережені версією 1.2: перевірка під час
  завантаження пропускає в них лише такі політики. Файл каталогу з такою політикою не імпортується зовсім.
- Групу «Провідник і робочий стіл» (раніше «Провідник: «Цей комп'ютер» і область переходів») поділено на «Папки в
  «Цей комп'ютер»», «Область переходів» і «Значки робочого столу», і вона отримала 26 нових правил: «Кошик» і «Панель
  керування» в «Цей комп'ютер»; показ або приховування пунктів області переходів («Бібліотеки», «Мережа», «Кошик»,
  «Панель керування», папка користувача, «Linux», USB-накопичувачі, усі папки, хмарні файли на «Головній»); значки на
  робочому столі. Усі нові правила вимкнені за замовчуванням, попередні правила групи зберегли свої ідентифікатори.
  Перевіряйте їх у віртуальній машині: частина відома лише зі сторонніх джерел (картка 20 довідника).
- Меню «Цей ПК»: «Застосувати вибране зараз...» і «Повернути вибране до стандартних значень Windows зараз...» для
  вимкнених правил «3D-об'єкти», «Кошик» і «Панель керування» в «Цей комп'ютер» записують `HiddenByDefault` = 1, як
  для інших папок «Цей комп'ютер», і так приховують ці пункти; раніше їх повертали лише вручну. Розділи реєстру не
  видаляються: якщо розділу не було, він створюється зі значенням 1. Що Windows приховує ці три пункти за цим
  значенням, ще треба перевірити у віртуальній машині.
- Обліковий запис під час інсталяції: у формі «Облікові записи» є режим «Запитати обліковий запис під час
  інсталяції». Тоді облікові записи й паролі не записуються у файл, інсталятор Windows запитує ім'я одного облікового
  запису, і він стає адміністратором; звичайний обліковий запис для роботи потрібно додати після інсталяції. Облікові
  записи форми залишаються в профілі. Перевірка попереджає, якщо вимкнено правила, без яких інсталятор вимагатиме
  обліковий запис Microsoft або зупиниться на екрані мережі. Профілі зберігаються у форматі 3.
- Випуск під час інсталяції: режим ключа «Вибрати випуск під час інсталяції» (раніше «Запитати ключ і випуск під час
  інсталяції») показує сторінку ключа продукту, а «У мене немає ключа продукту» відкриває список випусків. Поле випуску
  у формі «Інсталяція» доступне лише для універсального ключа. Перевірка нагадує, що захист WinKickOff розрахований на
  Pro: у Домашній не працюють відкладені оновлення компонентів і BitLocker, частина політик Copilot і Recall не
  підтримується.
- Список випусків для універсального ключа розширено: Pro N, Pro for Workstations і Pro for Workstations N, Pro
  Education і Pro Education N, Education N, Enterprise N, Enterprise G і Enterprise G N, Enterprise LTSC і Enterprise
  N LTSC. Крім Pro і Education, ключі списку є ключами клієнта KMS (GVLK) з таблиці Microsoft: така Windows
  активується сервером KMS організації, а без нього після інсталяції треба ввести ключ ліцензії. Вибраний випуск має
  бути на інсталяційному носії; форма «Інсталяція» нагадує про це під списком.
- Правило «Клавіші перемикання мови введення й розкладки клавіатури» (`default-user.input-switch-keys`, вимкнене за
  замовчуванням): лівий Alt+Shift, Ctrl+Shift або без клавіш, окремо для мови й для розкладки, для облікових записів,
  створених під час інсталяції та після неї, і для екрана входу. Win+Пробіл працює завжди. Перевірка не дає призначити
  мові й розкладці однакові клавіші. Меню «Цей ПК» не застосовує це правило до робочого комп'ютера.
- Безпека: параметри правил підставляються лише в записувані значення, ніколи в розділ реєстру чи ім'я значення, а
  шлях профілю користувача за замовчуванням записується в одинарних лапках. Раніше імпортований шаблон зі зловмисно
  складеними полями міг впровадити команду PowerShell у файл відповідей, і вона виконалася б під час інсталяції від
  імені SYSTEM, якщо ввімкнути таку політику. Файли відповідей попередніх збірок відкриваються як раніше.
- Сталі текстові значення імпортованих політик записуються як є: фігурні дужки в них (наприклад,
  `https://example.com/{id}`) залишаються текстом, а не вважаються параметром правила. Якщо збирання все ж не вдалося,
  «Перевірити» і «Зібрати autounattend.xml» показують помилку «Збирання неможливе: ...» у списку проблем, а сервер MCP
  повертає її як помилку збирання.
- Назва й автор профілю зберігаються одним рядком (переведення рядка стають пробілами), а в скриптах меню «Цей ПК»
  назва профілю завжди залишається в рядку коментаря. Раніше назва надісланого профілю з переведенням рядка могла
  додати до такого скрипту команду, яка виконалася б із правами адміністратора.
- Профіль неправильної форми відкривається: поле не того типу (наприклад, список замість об'єкта або текст замість
  числа) отримує значення за замовчуванням, зазвичай із попередженням, а решта налаштувань завантажується. Файл, який
  не є об'єктом JSON, не відкривається, і програма називає причину. Профіль читається так само суворо, як файли
  каталогу: з повтором ключа або з вкладеністю глибше 32 рівнів він не відкривається, зокрема всередині файлу
  відповідей, а файл профілю, більший за 16 МБ, не читається.
- Збереження профілю більше не може залишити порожній або недописаний файл: профіль пишеться в тимчасовий файл, який
  потім замінює попередній. Половина символу, яка лишається в полі введення, якщо емодзі стерто не повністю,
  зберігається як знак заміни (U+FFFD); раніше файл профілю в такому разі ставав порожнім. «Перевірити» називає поле з
  такою половиною символу, і файл відповідей не збирається, доки текст не виправлено.
- Сервер MCP: `set_param` більше не записує true або false у параметр із варіантами 0 і 1 (помилка
  `invalid_arguments`), а таке значення в профілі, збереженому через MCP версії 1.2, під час відкриття стає варіантом
  0 або 1, якому воно дорівнює. `get_profile` показує в імпортованої політики поле `source` (вид джерела вибору), а
  відкладені вибори містяться в `unknown`.
- Скрипти першого входу користувача й після первинного налаштування вміють записувати й видаляти значення реєстру
  (середовище виконання 0.6); це потрібно новим правилам області переходів.
- Гілка «Невідомі правила та політики» наприкінці дерева: якщо в профілі є вибір для правил, яких немає в
  завантаженому каталозі (політики прихованих або видалених імпортів, правила іншої версії WinKickOff), вікно показує
  їх там зі збереженим станом і параметрами. Опис називає збережений прихований імпорт, де є політика, і пропонує
  показати його знову; якщо такого імпорту немає, кнопки пропонують імпортувати шаблони того виду, з якого вибір
  повернеться. Такі записи не потрапляють у файл відповідей і не застосовуються.
- Вікно більше не виводить повідомлення Tcl, якщо його закрити одразу після введення в пошук.
- Контейнер `pi-agent` (помічник із локальною моделлю): pi знову працює зі своїми налаштуваннями за замовчуванням і
  режимом codemode, без обгортки 1.2.0-rc.3 і 1.2.0-rc.4, яка вимикала його інструменти й замінювала системні
  інструкції; образ встановлює pi 1.0.0 замість 0.99.2. Образ потрібно перезібрати (`pi-agent/README.md`).

Сумісність: профілі й файли відповідей версії 1.2 відкриваються як раніше (профіль формату 2 відкривається в режимі
«Створити ці облікові записи»). Перехід каталогу на JSON не змінив результат: чотири пресети збирають ті самі файли
відповідей, що й до переходу. Порівняно з 1.2.0-rc.4 у пресетах з'явилися 27 нових правил каталогу 0.6, і в усіх
чотирьох пресетах вони вимкнені; дії попередніх правил не змінювалися, а текст скриптів у файлі відповідей
відрізняється (функції реєстру в скриптах першого входу й після первинного налаштування, шлях профілю за
замовчуванням в одинарних лапках). Профіль, збережений у 1.3 (формат 3), версія 1.2 відкриє з попередженням про
формат і без режиму «Запитати обліковий запис під час інсталяції».

## English

The first candidate of version 1.3. Changes since 1.2.0-rc.4:

- The rule catalog is stored as JSON instead of TOML. Nothing changes for the user: the four presets and a profile with
  every rule on build the same answer files and scripts byte for byte, and the catalog version is still 0.6. The
  catalog files are read strictly: an unknown field (a misspelt name, for example) and a value of a wrong type are now
  catalog errors instead of values silently ignored or converted; a repeated key and null are errors too. A catalog
  translation file with an error is not loaded: the window and the MCP server show the rule texts in English.
  Translators edit the rule texts in `rules/lang/ru.json` and `rules/lang/uk.json`.
- Catalog files in the "ADMX" menu. "Export imported templates" saves the chosen import as one JSON file (the path of
  the original folder on this computer is not written into it). "Import a catalog file..." loads such a file (type
  "WinKickOff catalog": `.json`, also compressed `.json.gz` and `.json.xz`) on another computer that does not have the
  templates. The file is read and checked in the background, and the window does not hang meanwhile. When the same
  file is imported again, the program asks: "Yes" updates the earlier import (its tree and the choices in profiles
  stay), "No" adds one more tree, "Cancel" imports nothing. Import and export happen in the window only; they are not
  available through MCP.
- "Import a catalog of the program": catalogs of templates that ship with the program; importing one again updates
  the same tree and keeps a name the user gave it. The mechanism is ready, but no catalog ships yet: Microsoft
  templates will be included only after the license check, so the menu entry is greyed out for now.
- When two imports hold the same policy, the rule and its registry values come from the most trusted source: a catalog
  of the program, then the templates of this Windows, then a folder of templates, then a catalog file (within one kind,
  in the order of the trees). Before 1.3 the import loaded first won. The other trees show the policy with the same
  check mark, and the order of the trees does not change. A policy whose rule would take the place of a rule of another
  import (a policy named "Off" next to a policy with a rule for its Disabled state, for example) is not loaded and not
  shown instead of it. In 1.2 the rules of two policies of one import with the same id (no template of Windows has them)
  were numbered by their titles in the interface language; now they are numbered by the English titles, so the choices
  in a profile do not depend on the language.
- The profile remembers the kind of source a policy was chosen in (or the most trusted kind it was used from later).
  When a policy chosen, for example, in the templates of this Windows is now only in a catalog file (those templates
  are hidden or deleted), the choice does not move to the catalog file silently: opening the profile shows a warning,
  the choice stays in the tree root "Unknown rules and policies" and comes back when those templates are shown again.
  So the registry values of a less trusted file are not applied instead of the checked ones. A choice in a profile
  saved before 1.3 counts as made in templates from a folder (catalog files did not exist then), so it does not go to
  a catalog file without a warning either. The description of such a choice in the window explains why it is held and
  offers to show again or import only templates of the same or a more trusted kind; the warning is in the message list
  at the bottom of the window when the program starts and also after the window is rebuilt (a tree hidden, a catalog
  file imported).
- A catalog file is untrusted input, like template files: a file larger than 64 MB (also once unpacked) or with more
  than a million values is not read, every record is checked (known fields only, safe registry keys, value names and
  values, allowed number ranges, size limits), and on an error the file is not imported. A registry key may not have
  an empty part, "." or "..", and a name or a value may not contain control characters or characters that XML does
  not allow. The imports saved in the `admx` folder of the program are checked the same way every time they are
  loaded: an import with a damaged file (not strict JSON or too big, for example) or whose id in `import.json` differs
  from the name of its folder is not loaded, and the window says so, while single unsuitable policies in it are only
  skipped (next item). A crafted text in a catalog file can no longer hold up the start of the program for long.
- An odd or damaged policy in a folder of templates no longer stops the import: it is skipped (counted as "skipped"),
  and the other policies are imported. Imports saved by version 1.2 load the same way: the check on load skips only
  such policies in them. A catalog file with such a policy is not imported at all.
- The group "File Explorer and the desktop" (formerly "File Explorer: "This PC" and the navigation pane") is split into
  "Folders in "This PC"", "Navigation pane" and "Desktop icons" and has 26 new rules: "Recycle Bin" and "Control
  Panel" in "This PC"; showing or hiding items of the navigation pane ("Libraries", "Network", "Recycle Bin", "Control
  Panel", the user folder, "Linux", USB drives, all folders, cloud files in "Home"); icons on the desktop. Every new
  rule is off by default, and the earlier rules of the group keep their ids. Test them in a virtual machine: some are
  known from third-party sources only (card 20 of the reference).
- The "This PC" menu: "Apply the selection now..." and "Return the selection to Windows defaults now..." write
  `HiddenByDefault` = 1 for the rules "3D Objects", "Recycle Bin" and "Control Panel" in "This PC" when they are off,
  as for the other folders of "This PC", and so hide these entries; before, they were returned by hand only. Registry
  keys are not deleted: a key that did not exist is created with the value 1. That Windows hides these three entries
  by this value is still to be checked in a virtual machine.
- The account asked during installation: the "Accounts" form has the mode "Ask for the account during installation".
  The accounts and their passwords are then not written into the file; Windows Setup asks for the name of one account,
  which becomes an administrator, and a standard account for everyday work has to be added after installation. The
  accounts of the form stay in the profile. The check warns when a rule is off without which Setup demands a Microsoft
  account or stops at the network screen. Profiles are saved in format 3.
- The edition chosen during installation: the key mode "Choose the edition during installation" (formerly "Ask for
  the key and edition during installation") shows the product key page, and "I don't have a product key" opens the
  list of editions. The edition field of the "Installation" form is available only for the generic key. The check
  reminds that the WinKickOff protection is made for Pro: on Home, deferred feature updates and BitLocker do not work,
  and some Copilot and Recall policies are not supported.
- The edition list of the generic key is longer: Pro N, Pro for Workstations and Pro for Workstations N, Pro Education
  and Pro Education N, Education N, Enterprise N, Enterprise G and Enterprise G N, Enterprise LTSC and Enterprise N
  LTSC. Apart from Pro and Education, the keys of the list are the KMS client keys (GVLK) of the Microsoft table: such
  a Windows activates against a KMS server of the organisation, and without one the key of the license has to be
  entered after installation. The installation media must contain the chosen edition; the "Installation" form says so
  under the list.
- The rule "Keys that switch the input language and the keyboard layout" (`default-user.input-switch-keys`, off by
  default): left Alt+Shift, Ctrl+Shift or no keys, separately for the language and the layout, for accounts created
  during installation and later, and for the sign-in screen. Win+Space always works. The check does not let the
  language and the layout get the same keys. The "This PC" menu does not apply this rule to a running computer.
- Security: rule parameters are filled in only in the values that are written, never in a registry key or a value
  name, and the path of the default user profile is written in single quotes. Before, an imported template with
  crafted fields could inject a PowerShell command into the answer file, which would have run as SYSTEM during
  installation if such a policy was switched on. Answer files of earlier builds open as before.
- Fixed text values of imported policies are written as they are: braces in them (`https://example.com/{id}`, for
  example) stay text and are not taken for a rule parameter. If a build still fails, "Check" and "Build
  autounattend.xml" show the error "Cannot build: ..." in the list of problems, and the MCP server returns it as a
  build error.
- The name and the author of a profile are kept on one line (line breaks become spaces), and in the scripts of the
  "This PC" menu the profile name always stays on its comment line. Before, the name of a profile someone sent, with a
  line break in it, could add a command to such a script that would have run with administrator rights.
- A profile of a wrong shape opens: a field of the wrong type (a list instead of an object or text instead of a
  number, for example) gets its default value, usually with a warning, and the other settings load. A file that is
  not a JSON object does not open, and the program names the reason. A profile is read as strictly as the catalog
  files: with a repeated key or nested deeper than 32 levels it does not open, also inside an answer file, and a
  profile file larger than 16 MB is not read.
- Saving a profile can no longer leave an empty or half-written file: the profile goes to a temporary file that then
  replaces the old one. Half of a character, which an entry field keeps when an emoji is deleted in part, is saved as
  the replacement character (U+FFFD); before, the profile file was left empty in that case. "Check" names the field
  with such half of a character, and the answer file is not built until the text is corrected.
- The MCP server: `set_param` no longer writes true or false into a parameter with the options 0 and 1 (the error
  `invalid_arguments`), and such a value in a profile saved through MCP of version 1.2 becomes the option 0 or 1 it
  equals when the profile opens. `get_profile` shows the field `source` of an imported policy (the kind of source of
  the choice), and held choices are in `unknown`.
- The scripts of the first sign-in of a user and of the end of the out-of-box experience can write and delete registry
  values (runtime 0.6); the new navigation pane rules need this.
- The tree root "Unknown rules and policies" at the end of the tree: when the profile holds choices for rules the
  loaded catalog does not have (policies of hidden or deleted imports, rules of another version of WinKickOff), the
  window shows them there with their saved state and parameters. The description names the saved hidden import that
  has the policy and offers to show it again; when there is no such import, its buttons offer to import templates of a
  kind that brings the choice back. These entries are not written into the answer file and not applied.
- The window no longer prints a Tcl message when it is closed right after typing in the search field.
- The `pi-agent` container (an assistant with a local model): pi runs with its own defaults and the codemode exposure
  again, without the wrapper of 1.2.0-rc.3 and 1.2.0-rc.4 that switched off its tools and replaced its system
  instructions; the image installs pi 1.0.0 instead of 0.99.2. Rebuild the image (`pi-agent/README.md`).

Compatibility: profiles and answer files of version 1.2 open as before (a format 2 profile opens in the mode "Create
these accounts"). The move of the catalog to JSON did not change the result: the four presets build the same answer
files as before the move. Compared with 1.2.0-rc.4, the presets have the 27 new rules of catalog 0.6, off in all four
presets; the actions of the earlier rules did not change, while the text of the scripts in the answer file differs
(registry functions in the first sign-in and post-OOBE scripts, the default user profile path in single quotes). A
profile saved by 1.3 (format 3) opens in version 1.2 with a warning about the format and without the mode "Ask for the
account during installation".
