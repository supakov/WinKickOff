# WinKickOff 1.2.0-rc.3

## Русский

Третий кандидат версии 1.2. Новое и исправленное после 1.2.0-rc.2:

- Справка для помощников прямо с сервера MCP. Сервер отдаёт скилл `winkickoff` как ресурсы
  `winkickoff://skill/SKILL.md` и `winkickoff://skill/references/...`, а в начале сеанса подсказывает его прочитать.
  Помощник, у которого нельзя установить скилл или нет доступа к файлам, получает правила и сценарии работы с
  WinKickOff от самого сервера.
- Отказ инструмента теперь начинается с вида ошибки, например `mode_required: ...` (нужен другой режим) или
  `unsaved_changes: ...` (есть несохранённые изменения). Помощники с локальной моделью видят только текст ответа и
  теперь точно понимают, почему им отказано.
- Скилл: справочники разделены на файлы меньше 20 КБ (`tools.md`, `server.md`, `workflows.md`, `concepts.md`,
  `decisions.md`), чтобы ни один клиент не обрезал их середину.
- Контейнер `pi-agent` для помощника с локальной моделью работает только через MCP: репозиторий не подключается,
  встроенные инструменты pi (файлы, командная строка, правка) отключены, в образе только инструкции помощника. Образ
  нужно пересобрать, а из тома удалить старые ссылки (`pi-agent/README.md`, раздел о переходе).
- Для разработчиков: тесты не падают, когда служба буфера обмена Windows на мгновение занимает буфер, и не проверяют
  копии документации в папках `dist` и `build` предыдущей сборки.

Встроенные правила, пресеты и каталог 0.5 не менялись: файл ответов такой же, как из 1.2.0-rc.2.

## Українська

Третій кандидат версії 1.2. Нове й виправлене після 1.2.0-rc.2:

- Довідка для помічників просто із сервера MCP. Сервер віддає скіл `winkickoff` як ресурси
  `winkickoff://skill/SKILL.md` і `winkickoff://skill/references/...`, а на початку сеансу підказує його прочитати.
  Помічник, у якого не можна встановити скіл або немає доступу до файлів, отримує правила й сценарії роботи з
  WinKickOff від самого сервера.
- Відмова інструмента тепер починається з виду помилки, наприклад `mode_required: ...` (потрібен інший режим) або
  `unsaved_changes: ...` (є незбережені зміни). Помічники з локальною моделлю бачать лише текст відповіді й тепер
  точно розуміють, чому їм відмовлено.
- Скіл: довідники розділено на файли менші за 20 КБ (`tools.md`, `server.md`, `workflows.md`, `concepts.md`,
  `decisions.md`), щоб жоден клієнт не обрізав їхню середину.
- Контейнер `pi-agent` для помічника з локальною моделлю працює лише через MCP: репозиторій не підключається,
  вбудовані інструменти pi (файли, командний рядок, редагування) вимкнено, в образі лише інструкції помічника. Образ
  треба перезібрати, а з тому видалити старі посилання (`pi-agent/README.md`, розділ про перехід).
- Для розробників: тести не падають, коли служба буфера обміну Windows на мить займає буфер, і не перевіряють копії
  документації в папках `dist` і `build` попереднього збирання.

Вбудовані правила, пресети й каталог 0.5 не змінювалися: файл відповідей такий самий, як із 1.2.0-rc.2.

## English

The third candidate of version 1.2. New and fixed since 1.2.0-rc.2:

- Guidance for assistants straight from the MCP server. The server serves the `winkickoff` skill as the resources
  `winkickoff://skill/SKILL.md` and `winkickoff://skill/references/...` and suggests reading it at the start of a
  session. An assistant that cannot install skills or has no access to files gets the rules and recipes for working
  with WinKickOff from the server itself.
- A refused tool call now starts with the kind of the error, for example `mode_required: ...` (another mode is needed)
  or `unsaved_changes: ...` (there are unsaved changes). Assistants with a local model see only the text of the answer
  and now know exactly why they were refused.
- The skill: its references are split into files under 20 KB (`tools.md`, `server.md`, `workflows.md`, `concepts.md`,
  `decisions.md`), so no client cuts out their middle.
- The `pi-agent` container for an assistant with a local model works only through MCP: the repository is not mounted,
  pi's built-in tools (files, shell, editing) are off, and the image holds only the assistant's instructions. Rebuild
  the image and remove the old links from the volume (`pi-agent/README.md`, section "Migration from the old setup").
- For developers: the tests no longer fail when the Windows clipboard service holds the clipboard for a moment, and
  they no longer check the copies of the documentation in the `dist` and `build` folders of a previous build.

Built-in rules, presets and catalog 0.5 did not change: the answer file is the same as with 1.2.0-rc.2.
