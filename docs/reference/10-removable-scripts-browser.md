# 10. Съёмные носители, скриптовые файлы, Microsoft Edge

Раздел 6 `Setup-System.ps1`. Три вектора, через которые непрофессиональный пользователь чаще всего
запускает вредоносный код: флешка, вложение-скрипт, скачанный файл.

## DisableAutoRun

- Значение: `$true`.
- Что делает:
  - `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\Explorer\NoDriveTypeAutoRun = 255 (0xFF)`:
    автозапуск отключён для всех типов дисков (съёмные, фиксированные, сетевые, CD, RAM);
  - `...\Policies\Explorer\NoAutorun = 1`: файлы `autorun.inf` не обрабатываются даже для CD;
  - `Pol\Explorer\NoAutoplayfornonVolume = 1`: автовоспроизведение выключено для устройств без буквы
    диска (камеры, телефоны по MTP);
  - в профиле по умолчанию (раздел 14) `Explorer\AutoplayHandlers\DisableAutoplay = 1`: выключен
    диалог «Что делать с этим носителем?».
- Ожидаемый эффект: подключение флешки, диска или телефона ничего не запускает и ничего не спрашивает.
  Содержимое открывается только через проводник вручную.
- Кросс-связи: запуск файла с флешки вручную остаётся возможным; его покрывают правило ASR
  «недоверенные процессы с USB» (раздел 07) и облачная защита. Параметр в Параметрах → Устройства →
  Автозапуск становится серым.
- Различия версий: с Windows 7 (после обновления KB971029) `autorun.inf` на USB игнорируется всегда;
  для CD/DVD ещё работает, поэтому `NoAutorun` нужен. На 24H2 без изменений.
- Проверка: `Get-ItemProperty HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\Explorer`.
- Откат: удалить три значения.

## ScriptFilesOpenInNotepad

- Значение: `$true`.
- Что делает: для ProgId `JSFile`, `JSEFile`, `VBSFile`, `VBEFile`, `WSFFile`, `WSHFile`, `htafile`
  значение по умолчанию ключа `HKLM\SOFTWARE\Classes\<ProgId>\Shell\Open\Command` заменяется на
  `"%SystemRoot%\System32\notepad.exe" "%1"` (тип REG_EXPAND_SZ).
- Ожидаемый эффект: двойной щелчок по файлу `.js`, `.jse`, `.vbs`, `.vbe`, `.wsf`, `.wsh`, `.hta`
  (в том числе замаскированному под документ: `счёт.pdf.js`) открывает его текст в Блокноте, а не
  выполняет. Это закрывает классический сценарий фишинга «архив со скриптом внутри».
- Кросс-связи:
  - `cscript.exe file.vbs`, `wscript.exe file.vbs`, `mshta.exe file.hta` из командной строки и из
    программ работают: изменена только ассоциация оболочки. Установщики, которые запускают `.vbs`
    через `ShellExecute` (редко), откроют Блокнот; для них нужен откат для конкретного ProgId.
  - Ассоциация в HKCU (`Software\Classes\...`) перекрывает HKLM: пользователь, «восстановивший»
    ассоциацию через «Открыть с помощью», отменит защиту для себя.
  - Правило ASR «JavaScript/VBScript запускают скачанное» (раздел 07) и `RemoveVBScript` ниже
    покрывают запуск через движок напрямую.
  - Показ расширений файлов в профиле по умолчанию (раздел 14) даёт пользователю шанс увидеть `.js`.
- Различия версий: ProgId одинаковы с Windows XP. В Windows 11 24H2 VBScript переведён в
  необязательный компонент (см. ниже), но по умолчанию ещё установлен, и ассоциации существуют.
- Проверка: `(Get-ItemProperty 'HKLM:\SOFTWARE\Classes\VBSFile\Shell\Open\Command').'(default)'`.
- Откат: восстановить значения по умолчанию, например для VBS:
  `"%SystemRoot%\System32\WScript.exe" "%1" %*`; для JS то же с `WScript.exe`; для HTA
  `"%SystemRoot%\System32\mshta.exe" "%1" %*`.

## RemoveVBScript

- Значение: `$false` (движок оставлен).
- Что делает при `$true`: `Remove-WindowsCapability -Online -Name VBSCRIPT~~~~` (все версии).
- Ожидаемый эффект при `$true`: интерпретатор VBScript удалён; ни `.vbs`, ни макросы на VBScript
  в старых программах, ни компонент `MSScriptControl` не работают.
- Почему выключено: установщики программ 2000-х годов, часть драйверов принтеров и старые
  корпоративные приложения используют VBScript; на 24H2 движок ещё нужен и системным компонентам
  сторонних поставщиков. Ассоциация на Блокнот (выше) даёт большую часть защиты без поломок.
- Кросс-связи: JScript удалить нельзя (не компонент); его покрывают ассоциации и ASR.
- Различия версий: компонент `VBSCRIPT~~~~` существует только в Windows 11 24H2 и новее; на 23H2 и
  Windows 10 движок неотделим, команда запишет WARN и ничего не сделает. Microsoft планирует удалить
  VBScript из образа в будущих версиях.
- Проверка: `Get-WindowsCapability -Online -Name 'VBSCRIPT*'`.
- Откат: `Add-WindowsCapability -Online -Name VBSCRIPT~~~~` (нужен интернет или источник).

## EdgeSmartScreenLocked и безусловные политики Edge

Edge сохранён как «аварийный» браузер: без него после установки нельзя скачать другой браузер.
Политики в `HKLM\SOFTWARE\Policies\Microsoft\Edge`.

| Политика | Значение | Условие | Эффект |
|---|---|---|---|
| SmartScreenEnabled | 1 | EdgeSmartScreenLocked | Проверка сайтов и загрузок по репутации |
| SmartScreenPuaEnabled | 1 | EdgeSmartScreenLocked | Блокировка нежелательных загрузок |
| PreventSmartScreenPromptOverride | 1 | EdgeSmartScreenLocked | Пользователь не может «перейти на сайт» после предупреждения |
| PreventSmartScreenPromptOverrideForFiles | 1 | EdgeSmartScreenLocked | Пользователь не может «сохранить всё равно» заблокированный файл |
| HideFirstRunExperience | 1 | всегда | Нет мастера первого запуска и предложений импорта |
| ShowRecommendationsEnabled | 0 | всегда | Нет рекламных подсказок в интерфейсе |
| PersonalizationReportingEnabled | 0 | всегда | Данные о просмотре не отправляются для персонализации рекламы |
| StartupBoostEnabled | 0 | всегда | Edge не висит в памяти после закрытия |
| BackgroundModeEnabled | 0 | всегда | Нет фоновых процессов Edge |

- Ожидаемый эффект: Edge защищает от фишинга и вредоносных загрузок без возможности обойти
  предупреждение одним кликом; не показывает рекламу; не занимает память в фоне.
- Кросс-связи: SmartScreen Edge не заменяет SmartScreen оболочки (раздел 07): первый работает
  при загрузке, второй при запуске файла. Другие браузеры (Chrome, Firefox) этими политиками не
  управляются; сетевая защита Defender (раздел 07) покрывает и их. Политики делают соответствующие
  пункты в `edge://settings` серыми.
- Различия версий: политики Edge поддерживаются с Edge 77+ (2019) и обновляются вместе с браузером,
  независимо от версии Windows. `PreventSmartScreenPromptOverrideForFiles` с Edge 79.
- Проверка: `edge://policy` показывает все девять с источником «Machine».
- Откат: удалить значения из ключа политик.
