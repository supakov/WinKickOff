# 11. Журналирование для расследования инцидентов

Раздел 7 `Setup-System.ps1`. Цель: когда на одном ПК рабочей группы что-то случится, в журналах
должно быть достаточно данных, чтобы понять, как это произошло: какой процесс запустился, с какой
командной строкой, под каким пользователем, что делал PowerShell. Штатно Windows пишет минимум.

## AuditLogging

- Значение: `$true`.
- Что делает:
  1. `Sys\Audit\ProcessCreationIncludeCmdLine_Enabled = 1`: событие 4688 «создан процесс» включает
     полную командную строку (без этого видно только имя exe).
  2. `auditpol.exe /set /subcategory:{GUID} /success:enable /failure:enable` для десяти подкатегорий
     (таблица ниже). Подкатегории заданы по GUID, потому что на украинском образе auditpol
     принимает только локализованные имена; GUID не зависят от языка.
  3. `auditpol.exe /set /subcategory:{0CCE922C-...} /success:disable /failure:disable`: завершение
     процессов не журналируется (шум).
  4. `wevtutil.exe sl <журнал> /ms:<байты>`: размеры журналов: Security 256 МБ, System 64 МБ,
     Application 64 МБ, `Microsoft-Windows-PowerShell/Operational` 128 МБ (умолчания 20 МБ и 15 МБ).

| GUID | Подкатегория | Что даёт |
|---|---|---|
| 0CCE922B-69AE-11D9-BED3-505054503030 | Создание процесса | 4688: кто, что, с какими аргументами запустил |
| 0CCE9215-69AE-11D9-BED3-505054503030 | Вход | 4624/4625: успешные и неудачные входы, включая сетевые |
| 0CCE9216-69AE-11D9-BED3-505054503030 | Выход | 4634/4647 |
| 0CCE9217-69AE-11D9-BED3-505054503030 | Блокировка учётной записи | 4740 |
| 0CCE921B-69AE-11D9-BED3-505054503030 | Особый вход | 4672: вход с правами администратора |
| 0CCE9235-69AE-11D9-BED3-505054503030 | Управление учётными записями | 4720/4722/4724/4726: создание, включение, смена пароля, удаление |
| 0CCE9237-69AE-11D9-BED3-505054503030 | Управление группами безопасности | 4732/4733: добавление в Администраторы |
| 0CCE923F-69AE-11D9-BED3-505054503030 | Проверка учётных данных | 4776: NTLM-аутентификация, перебор паролей |
| 0CCE9227-69AE-11D9-BED3-505054503030 | Другие события доступа к объектам | 4698/4702: создание и изменение задач планировщика (закрепление) |
| 0CCE9245-69AE-11D9-BED3-505054503030 | Съёмное хранилище | 4663 для файлов на USB: что скопировали на флешку |

- Ожидаемый эффект: журнал Security на обычном офисном ПК заполняет 256 МБ за 2-6 недель; при
  инциденте есть история за этот период. Сопоставление 4688 с командной строкой и 4624 по времени
  показывает цепочку заражения.
- Кросс-связи:
  - `auditpol` меняет локальную политику аудита. Групповая политика домена перекрыла бы её, но
    домена нет. Через `secpol.msc` (Расширенная политика аудита) значения видны и редактируемы.
  - Правильное время (`TimeZone`, раздел 02, и синхронизация) обязательно для сопоставления событий.
  - Журналы хранятся на самом ПК; при шифровании диска вымогателем они теряются. Следующий шаг
    (не в этой версии): пересылка событий на общий ресурс или сборщик (Windows Event Forwarding).
  - Аудит съёмных носителей пишет много событий при копировании больших папок на флешку.
- Различия версий: подкатегория «Съёмное хранилище» с Windows 8. Командная строка в 4688 с
  Windows 8.1 / KB3004375 для Windows 7. GUID подкатегорий одинаковы во всех версиях.
  На 24H2 без изменений.
- Проверка: `auditpol /get /category:*`; `wevtutil gl Security | findstr maxSize`;
  Просмотр событий → Security → событие 4688 содержит поле «Командная строка процесса».
- Откат: `auditpol /clear` (все подкатегории в «без аудита»); размеры журналов:
  `wevtutil sl Security /ms:20971520`.

## PowerShellLogging

- Значение: `$true`.
- Что делает:
  - `Pol\PowerShell\ScriptBlockLogging\EnableScriptBlockLogging = 1`: текст каждого выполняемого
    блока кода пишется в `Microsoft-Windows-PowerShell/Operational`, событие 4104, включая
    деобфусцированный код (то, что реально выполняется после раскрытия строк);
  - `Pol\PowerShell\ModuleLogging\EnableModuleLogging = 1` и `ModuleNames\* = *`: вызовы командлетов
    всех модулей с параметрами, событие 4103.
- Ожидаемый эффект: вредоносные загрузчики на PowerShell (самый частый тип после скриптов почты)
  оставляют полный текст в журнале, даже если файл скрипта удалён.
- Кросс-связи:
  - Размер журнала PowerShell поднят до 128 МБ в `AuditLogging`; без этого 15 МБ заполняются за дни.
  - Журнал может содержать чувствительные данные, если администратор передаёт пароли в командной
    строке; доступ к журналу только у администраторов.
  - Действует на Windows PowerShell 5.1 и PowerShell 7 (тот читает те же политики).
  - `Setup-System.ps1` сам включает эту политику по ходу выполнения; последующие скрипты
    (`Setup-User.ps1`, `Post-OOBE.ps1`) уже журналируются.
- Различия версий: Script Block Logging с Windows 10 / WMF 5.0; на Windows 7 требует WMF 5.1.
  На 24H2 без изменений. Транскрипция (`EnableTranscripting`) не включена: пишет файлы в профили
  пользователей, которые они могут удалить.
- Проверка: `Get-ItemProperty 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging'`;
  журнал содержит события 4104 после любого запуска PowerShell.
- Откат: удалить два ключа.

## DisablePowerShellV2

- Значение: `$true`.
- Что делает: `Disable-WindowsOptionalFeature` для `MicrosoftWindowsPowerShellV2Root` и
  `MicrosoftWindowsPowerShellV2`, если они включены.
- Ожидаемый эффект: `powershell.exe -Version 2` не запускается. Движок 2.0 не поддерживает
  журналирование блоков кода и AMSI (проверку антивирусом), поэтому вредоносные скрипты просят
  именно его («downgrade attack»).
- Кросс-связи: программы, требующие .NET 2.0/3.5 (включены через `EnableNetFx3`), не зависят от
  PowerShell 2.0. Ни один современный продукт Microsoft движок 2.0 не использует.
- Различия версий: компонент существует в Windows 10 и Windows 11 до 23H2 (по умолчанию включён на
  Windows 10 и выключен на Windows 11). В Windows 11 24H2 с обновлением августа 2025 и в 25H2 движок
  удалён из образа полностью: команда запишет INFO об отсутствии компонента, это ожидаемо.
- Проверка: `Get-WindowsOptionalFeature -Online -FeatureName MicrosoftWindowsPowerShellV2Root`;
  `powershell -Version 2 -Command 1` должна завершиться ошибкой.
- Откат: `Enable-WindowsOptionalFeature -Online -FeatureName MicrosoftWindowsPowerShellV2Root`
  на сборках, где он есть.
