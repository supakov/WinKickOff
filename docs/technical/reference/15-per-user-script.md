# 15. Active Setup и Setup-User.ps1: настройки первого входа каждого пользователя

Раздел 11 `Setup-System.ps1` регистрирует механизм; сам скрипт встроен в XML как
`C:\ProgramData\Unattend\Scripts\Setup-User.ps1`.

## Механизм Active Setup

- Ключ: `HKLM\SOFTWARE\Microsoft\Active Setup\Installed Components\{7A6C3F5E-2B1D-4C8E-9F0A-5D3E6B7C8D91}`.
- Значения: `(Default) = Workgroup per-user setup`, `StubPath = powershell.exe -NoProfile
  -ExecutionPolicy Bypass -WindowStyle Hidden -File "C:\ProgramData\Unattend\Scripts\Setup-User.ps1"`,
  `Version = 1,0,0,0`, `IsInstalled = 1`.
- Как работает: при входе пользователя Windows сравнивает `Version` в HKLM с копией в
  `HKCU\Software\Microsoft\Active Setup\Installed Components\{GUID}`. Если копии нет или версия старше,
  запускается `StubPath` от имени пользователя, синхронно, до старта проводника, затем версия
  копируется в HKCU. Повторно для того же пользователя не выполняется.
- Ожидаемый эффект: первый вход каждого пользователя (Admin, User, любого созданного позже)
  задерживается на 3-10 секунд, пока скрипт переставляет языки ввода. Окно не показывается.
- Почему не FirstLogonCommands и не задача планировщика: FirstLogonCommands выполняются один раз
  для первого вошедшего; задача от SYSTEM не имеет доступа к HKCU нужного пользователя без
  сложной подмены токена (так делал оригинальный файл). Active Setup штатен с Windows 98 и работает
  во всех версиях Windows 10/11.
- Кросс-связи: `-ExecutionPolicy Bypass` обязателен (политика по умолчанию Restricted).
  Скрипт работает без повышения прав: всё, что он делает, относится к HKCU текущего пользователя.
  Изменив `Version` на `1,0,0,1`, администратор заставит скрипт выполниться повторно у всех
  при следующем входе (способ доставить новую версию настроек).
- Различия версий: нет.
- Проверка: `Get-ItemProperty 'HKCU:\Software\Microsoft\Active Setup\Installed Components\{7A6C3F5E-2B1D-4C8E-9F0A-5D3E6B7C8D91}'`
  после входа; лог `C:\ProgramData\Unattend\Logs\Setup-User.<имя>.log`.
- Откат: удалить ключ в HKLM (новые пользователи не получат); удалить копию в HKCU (повторный запуск).

## Что делает Setup-User.ps1

Лог: `C:\ProgramData\Unattend\Logs\Setup-User.<имя пользователя>.log`. Отдельный файл на каждого,
потому что файл, созданный первым пользователем в ProgramData, не даёт права записи второму.

### Шаг 1. Закрепление языка интерфейса

`Set-WinUILanguageOverride -Language <InstalledUICulture>`: язык интерфейса явно фиксируется равным
языку образа. Без этого Windows выводит язык интерфейса из первого языка в списке предпочтений, и
перестановка списка ниже (английский первым) переключила бы интерфейс на английский после
следующего входа. Требование заказчика «язык интерфейса не менять» держится на этой строке.

- Различия версий: командлет с Windows 8. На Windows 11 22H2+ страница «Язык и регион» показывает
  «Язык интерфейса Windows» отдельно от списка языков; override соответствует этому.
- Откат: `Set-WinUILanguageOverride` без параметра снимает закрепление.

### Шаг 2. Список языков ввода

1. Создаётся список: `en-US`, затем `uk-UA`, затем `ru-UA` («Русский (Украина)»).
2. `Set-WinUserLanguageList -Force`: применяется без вопроса.
3. Проверка: `Get-WinUserLanguageList` должен содержать `ru-UA` с непустым `InputMethodTips`.
   На сборке 26200 Windows назначает ему временный идентификатор `2000:00000419`, то есть русскую
   раскладку под временным кодом языка (в реестре `Keyboard Layout\Preload` появляется `00002000`
   с подстановкой `Substitutes\00002000 = 00000419`).
4. Если `ru-UA` отсутствует или без раскладки, либо любая команда упала: запасной список `en-US`,
   `uk-UA`, `ru` (обычный «Русский»), тоже с `-Force`.

- Ожидаемый эффект: в переключателе языков пользователя ENG, УКР, РУС, где РУС отображается как
  «Русский (Украина)» и в Параметрах числится с регионом Украина. Порядок совпадает с экраном входа.
- Кросс-связи:
  - Экран входа и профиль по умолчанию получили список из `InputLocale` (раздел 03) с обычным
    русским; скрипт меняет только список текущего пользователя. Расхождение (экран входа «Русский»,
    пользователь «Русский (Украина)») ожидаемо и безвредно.
  - Раскладка украинского в списке пользователя: `0422:00020422` (расширенная), как и в XML.
  - Языковые пакеты для `ru-UA` не нужны: это язык ввода, а не интерфейса; Windows не пытается
    скачать LXP.
  - Изменение пользователем списка в Параметрах остаётся: скрипт больше не запускается.
  - Тест на рабочем ПК заказчика 12.09.2026 показал, что `Set-WinUserLanguageList` меняет живой
    сеанс не полностью синхронно с реестром; для нового пользователя при первом входе это не
    проявляется, потому что сеанс только создаётся.
- Различия версий: `ru-UA` как язык ввода поддерживается в Windows 10 1803+ и Windows 11 (список
  CLDR); на более старых сборках сработает запасной вариант. Командлеты модуля International
  есть во всех версиях.
- Проверка: `Get-WinUserLanguageList | Select LanguageTag, InputMethodTips` под учётной записью
  пользователя; лог содержит строку `applied: en-US[0409:00000409] uk-UA[0422:00020422] ru-UA[2000:00000419]`.
- Откат: Параметры → Язык и регион, либо `Set-WinUserLanguageList` с нужным списком.

### Завершение

`exit 0`. Active Setup не анализирует код возврата, но единообразие с остальными скриптами сохранено.
