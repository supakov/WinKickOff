# 20. File Explorer namespaces and desktop icons

Rules of the customer request of 04.10.2026: "check the key of 3D Objects in This PC and add it if it is missing;
add options for all namespaces of Windows 10 and 11, not only This PC, with all icons available in all editions".
The rules are generated by `WinKickOff/tools/make_shell_rules.py` into `WinKickOff/rules/17-shell.toml`; the twelve
folders of "This PC" and three navigation pane rules of card 19 (`16-explorer.toml`) belong to the same group,
"File Explorer and the desktop". Every rule is off by default, so Windows keeps its own choice; only
`nav.gallery-hidden` (card 19) is on.

How the entries were checked (04.10.2026): read-only registry queries on Windows 11 build 26300 (the editing PC; the
target ISO is 26200, so a value seen only there is a hint, not a proof), the ADMX templates of that Windows,
Microsoft Learn where Microsoft documents the mechanism, and third-party sources where it does not. The column
"Check" uses D for Microsoft documentation, A for the ADMX of Windows, R for a read-only registry query and T for
third-party reports only. The shell entries are the same in every edition of Windows 10 and 11; WinKickOff itself
targets Pro (the README of the reference says why the Windows Home edition is not supported). The one policy of the
card, `nav.home-cloud-files-off`, has no edition limit in Explorer.admx; the Policy CSP lists Pro, Enterprise and
Education because it describes delivery through MDM.

## This PC

`HKLM\SOFTWARE\[WOW6432Node\]Microsoft\Windows\CurrentVersion\Explorer\MyComputer\NameSpace\{CLSID}`, phase
specialize, both branches so that the file dialogs of 32-bit programs match File Explorer. Windows 11 22H2 and later
keep the user folders there with `HiddenByDefault` = 1; the rules write 0 (card 19). An entry that Windows does not
ship is created by the rule; the automatic return to Windows defaults does not delete keys.

|---|---|---|---|
| `thispc.3d-objects` (card 19) | {0DB7E03F-FC29-4DC6-9020-FF41B59E513A} | 3D Objects | R: the key is absent in both branches of 26300, the item is still registered (known folder {31C0DD25-9439-4F12-BF41-7FF4EDA38722}, `PreCreate` 0); T: creating the key brings the entry back |
| `thispc.recycle-bin` | {645FF040-5081-101B-9F08-00AA002F954E} | Recycle Bin | T |

The delegate folders of This PC (portable devices, DLNA media servers, enhanced storage, network locations) are not
offered: removing them hides phones, cameras and mapped network locations.

## Navigation pane

The root of the navigation pane and of the desktop is `...\Explorer\Desktop\NameSpace` (both branches). Whether an
item shows in the pane is the value `System.IsPinnedToNameSpaceTree` (DWORD, 1 shows, 0 hides) of its CLSID; D:
Microsoft documents it for cloud storage providers under `HKCU\Software\Classes\CLSID`.

- The machine registration `HKLM\SOFTWARE\Classes\CLSID\{...}` of every item below except Linux belongs to
  TrustedInstaller, and SYSTEM may only read it (R), so a script of Windows Setup cannot change it. The Linux item is
  registered by WSL when WSL is installed, which happens after Windows Setup, so its pin is per user as well.
- The classes of a user (`HKCU\Software\Classes`) come from `UsrClass.dat`, not from `NTUSER.DAT`, so the default
  profile written in phase default-user does not reach them (R; T: values written into the default profile had no
  effect, the same values set after sign-in worked).
- So the pins are written per user at the first sign-in (phase user-first-logon, Active Setup), into
  `HKCU\Software\Classes\CLSID\{...}` and its `WOW6432Node` twin for 32-bit file dialogs. Runtime 0.6 added Set-Reg
  and Remove-Reg to `Setup-User.ps1` for this; until then a registry action of that phase failed. "Apply" on a running
  PC does not run first sign-in rules.

Other rules of the pane:

- `nav.show-all-folders`: `DU:\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced`, `NavPaneShowAllFolders` = 1
  (D for the option "Show all folders", T for the value name).
- `nav.removable-drives-once`: deletes `...\Explorer\Desktop\NameSpace\DelegateFolders\{F5FB2C77-0E2F-4A16-A381-3E560C68BC83}`
  in both branches, so USB drives are listed only under This PC (T; a feature update may create the key again).
- `nav.home-cloud-files-off`: `HKLM\SOFTWARE\Policies\Microsoft\Windows\Explorer`, `DisableGraphRecentItems` = 1,
  Windows 11 22H2 and later. D: Policy CSP FileExplorer/DisableGraphRecentItems, "1: File Explorer won't request cloud
  file metadata or display it in the homepage or other views", friendly name "Turn off account-based insights, recent,
  favorite, and recommended files in File Explorer". A: Explorer.admx writes the same 1 when its policy, named "Show
  files based on your account and cloud provider activity", is enabled; the name of the ADMX reads the other way round.
- `nav.gallery-hidden` and `nav.home-hidden` (card 19) write `HiddenByDefault` = 1 under `Desktop\NameSpace`.
  Windows itself uses `HiddenByDefault` only under `MyComputer\NameSpace` (R); that it works under `Desktop\NameSpace`
  is reported by third parties only. Check it in the virtual machine; if it has no effect, a per-user pin (value 0)
  for the same CLSIDs is the fallback.

The Group Policy settings that hide such items for good (`NoMyComputerIcon`, `NoRecycleBinIcon` and the other
`NonEnum` values of Desktop.admx, `NoDesktop`) are too broad for this project and are not offered; OneDrive in the
pane is covered by `apps.remove.onedrive` and `onedrive.block`.

## Desktop icons

`DU:\Software\Microsoft\Windows\CurrentVersion\Explorer\HideDesktopIcons\NewStartPanel` and `\ClassicStartMenu`, a
DWORD named after the CLSID, 0 shows and 1 hides, phase default-user, so every account created during or after the
installation gets it; this is what the Desktop icon settings dialog writes (D-archive: Microsoft's USMT notes; R: the
values of this PC's user after the dialog). Windows keeps machine defaults with value 1 under
`HKLM\...\HideDesktopIcons\NewStartPanel` for every icon of the tables below except Recycle Bin and the Spotlight icon
(R); the per-user values override them. The Spotlight icon has no machine default: Windows shows it whenever Windows
Spotlight is the desktop background.

The Desktop icon settings dialog offers only the first five icons of the table below. The other rules write values
of the same form; a user who wants such an icon back (or gone) deletes the value under
`HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\HideDesktopIcons`, as the rollback of each rule says.

## What is not offered, and why

- The other junction roots that Microsoft lists for namespace extensions (`ControlPanel\NameSpace`,
  `NetworkNeighborhood`, `RemoteComputer`, `UsersFiles`) and the internal roots of Home have no documented
  installation-time switch; Control Panel items are hidden through the policy `DisallowCpl` instead.
- Changing the icons or attributes of system CLSIDs: TrustedInstaller owns them.
- Windows 10 only: Quick access `HubMode`, `ThisPCPolicy`. WinKickOff targets Windows 11 24H2 and 25H2.

## Checks in a virtual machine

1. With the Office preset plus the rules of this card: the new entries in This PC, the pane and on the desktop of
   Admin and User; `Setup-User.<user>.log` shows the `System.IsPinnedToNameSpaceTree` lines with OK.
2. `HiddenByDefault` under `Desktop\NameSpace` (`nav.gallery-hidden`, on by default): Gallery is gone from the pane.
3. 3D Objects on 25H2: the entry opens; whether the folder `%USERPROFILE%\3D Objects` is created then.
4. The per-user pin of Control Panel (`nav.control-panel`).
5. An account created after installation gets the desktop icons of the default profile.

## Verification and rollback

Each rule has its own check (`reg query`) and rollback text. On a running PC, "Return the selection to Windows
defaults now..." removes the values of the default profile (`desktop.*`, `nav.show-all-folders`; Windows default
"absent"), which only accounts created later notice. It does not run first sign-in rules, so the per-user pins of
`nav.*` are neither applied nor returned there; remove them by hand as the rule describes. It does not delete the
keys that `thispc.*` creates, and it cannot restore the delegate folder that `nav.removable-drives-once` deletes.
