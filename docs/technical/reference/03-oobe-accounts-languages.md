# 03. Проход oobeSystem: языки и регион, экраны OOBE, стартовые учётные записи

## Компонент Microsoft-Windows-International-Core

Все четыре значения заданы. По документации «Automate OOBE» экран выбора языка и региона
пропускается только если заданы все четыре; иначе OOBE спросит недостающее.

### InputLocale

- Значение: `0409:00000409;0422:00020422;0419:00000419`.
- Что делает: список языков ввода для экрана входа и профиля пользователя по умолчанию, в порядке:
  1. `0409:00000409` английский (США), раскладка US;
  2. `0422:00020422` украинский, раскладка «Украинская (расширенная)» (с апострофом и Ґ на штатных клавишах);
  3. `0419:00000419` русский, раскладка «Русская».
  Первый в списке становится языком ввода по умолчанию.
- Ожидаемый эффект: на экране входа переключение ENG → УКР → РУС. Новые пользователи получают тот же список.
- Кросс-связи: «Русский (Украина)» (`ru-UA`) здесь записать нельзя: у него нет числового кода языка
  (LCID 0x1000, временный идентификатор назначается системой). Его подставляет `Setup-User.ps1` при
  первом входе каждого пользователя (раздел 15). До этого у пользователя стоит обычный «Русский».
- Различия версий: формат `LCID:KLID` одинаков для Windows 7 и новее. Раскладка `00020422` есть
  в Windows 8 и новее. Windows 11 при первом входе может добавить язык региона (`uk-UA` уже есть).
- Проверка: на экране входа индикатор языка; в системе `Get-WinUserLanguageList` у нового пользователя.
- Откат: Параметры → Время и язык → Язык и регион, либо `Set-WinUserLanguageList`.

### SystemLocale

- Значение: `uk-UA`.
- Что делает: язык для программ, не поддерживающих Юникод (кодовая страница ANSI 1251, OEM 866).
- Ожидаемый эффект: старые программы (1С 7.7, старые учётные системы, консольные утилиты) показывают
  кириллицу вместо «кракозябр». Кодовая страница 1251 общая для украинского и русского, так что
  выбор `uk-UA` покрывает и русскоязычные старые программы.
- Кросс-связи: не влияет на язык интерфейса и ввод. Изменение требует перезагрузки. Параметр
  «Бета: использовать Юникод UTF-8» не включён (он ломает часть старых программ).
- Различия версий: нет.
- Проверка: `Get-WinSystemLocale`.
- Откат: `Set-WinSystemLocale ru-RU` (или другой) и перезагрузка.

### UILanguage

- Значение: `uk-UA`.
- Что делает: язык интерфейса системы. Должен совпадать с языком ISO: значение, которого нет в
  образе, игнорируется, а отсутствие значения вызывает экран выбора языка в OOBE.
- Ожидаемый эффект: интерфейс на языке ISO, экран языка в OOBE не показывается. Требование заказчика
  «язык интерфейса не менять» выполняется: значение равно языку образа, а не меняет его.
- Кросс-связи: `Setup-User.ps1` дополнительно закрепляет язык интерфейса через
  `Set-WinUILanguageOverride`, чтобы перестановка языков ввода не переключила интерфейс.
  При смене ISO на англоязычный значение нужно заменить на `en-US` (параметр конструктора,
  вычисляется из ISO).
- Различия версий: в Windows 11 22H2 и новее языковые пакеты ставятся как LXP через Store;
  если задать язык, которого нет в образе, система останется на языке образа без ошибки.
- Проверка: `Get-WinSystemLocale`, `dism /online /get-intl`, `[CultureInfo]::InstalledUICulture`.
- Откат: Параметры → Язык и регион → Язык интерфейса Windows.

### UserLocale

- Значение: `uk-UA`.
- Что делает: региональный формат: даты `дд.мм.рррр`, время 24 ч, десятичный разделитель запятая,
  валюта ₴, первый день недели понедельник.
- Ожидаемый эффект: Excel, бухгалтерские программы и проводник показывают даты и числа в украинском формате.
- Кросс-связи: регион (страна) задаётся отдельно в профиле по умолчанию (`Geo\Nation=241`, раздел 14).
  Формат влияет на разбор CSV и импорт данных в программах учёта: разделитель списка «;».
- Различия версий: нет.
- Проверка: `Get-Culture`.
- Откат: Параметры → Язык и регион → Региональный формат.

## Компонент Microsoft-Windows-Shell-Setup / OOBE

| Элемент | Значение | Что скрывает или задаёт | Примечание |
|---|---|---|---|
| HideEULAPage | true | Экран лицензии в OOBE | В установщике лицензия принята через `AcceptEula` |
| HideOEMRegistrationScreen | true | Экран регистрации у производителя | Появляется только на OEM-образах |
| HideOnlineAccountScreens | true | Экраны входа в учётную запись Microsoft и создания локальной учётной записи | Работает потому, что учётные записи заданы в `LocalAccounts` |
| HideWirelessSetupInOOBE | true | Экран «Подключитесь к сети» | Экран и так пропускается при проводном подключении; здесь он скрыт всегда |
| ProtectYourPC | 3 | Экран параметров конфиденциальности | 3 = отключить все «экспресс-параметры»: отправка данных, реклама, определение местоположения. SmartScreen и Defender не затрагиваются: они включаются отдельно в `Setup-System.ps1` |

- Ожидаемый эффект: после specialize система показывает только анимацию подготовки и сразу экран
  входа с двумя учётными записями. Ни одного вопроса.
- Кросс-связи: экран языка скрыт через International-Core; экран раскладки скрыт через `InputLocale`;
  экраны сети и учётной записи через `HideOnlineAccountScreens` + `LocalAccounts` + `BypassNRO`.
  Экраны, которые Windows 11 показывает после входа («Завершим настройку устройства»), отключены
  в профиле по умолчанию (`ScoobeSystemSettingEnabled=0`, раздел 14).
- Различия версий: `ProtectYourPC=3` на Windows 11 24H2 работает; `HideLocalAccountScreen` не
  используется (нужен только при автологоне встроенного администратора). На Windows 10 те же элементы.
- Проверка: установка проходит без единого экрана после выбора диска.
- Откат: не применимо.

## UserAccounts / LocalAccounts

Две учётные записи, порядок дочерних элементов как в примере документации Microsoft
(Password, Description, DisplayName, Group, Name).

| Поле | Admin | User |
|---|---|---|
| Name | Admin | User |
| DisplayName | Admin | User |
| Description | Local administrator (starter account) | Standard user (starter account) |
| Group | Administrators | Users |
| Password/Value | пусто | пусто |
| Password/PlainText | true | true |

- Что делает: OOBE создаёт обе учётные записи до первого входа. Профили (папки `C:\Users\Admin`,
  `C:\Users\User`) создаются при первом входе каждого, поэтому они наследуют профиль по умолчанию,
  изменённый в specialize (раздел 14).
- Ожидаемый эффект: на экране входа две плитки, вход без пароля по щелчку.
- Кросс-связи:
  - Пустой пароль и `LimitBlankPasswordUse=1` (штатно): вход по сети, RDP, `runas` и подтверждение
    UAC учётными данными Admin невозможны до назначения паролей. Стандартный пользователь User
    не сможет повысить права (ошибка 1327). Программы до назначения паролей устанавливаются из-под Admin.
  - `PasswordNeverExpires` (раздел 04) не даёт требовать смену пароля через 42 дня.
  - Имена `Admin` и `User` продублированы в `$Config.AdminAccount` и `$Config.UserAccount`:
    их использует `Post-OOBE.ps1`. Менять нужно в обоих местах (конструктор сделает это из одного поля).
  - Группа `Administrators` указана по английскому имени; на локализованных образах Setup
    сопоставляет встроенные группы корректно (проверить после установки командой ниже).
  - Встроенные `Administrator` (RID 500) и `Guest` (RID 501) остаются отключёнными; Post-OOBE.ps1
    проверяет это по SID.
- Различия версий: Windows 11 24H2 сохраняет копию файла с именами (и паролями, если бы они были)
  в `C:\Windows\Panther\unattend.xml` и `unattend-original.xml`; Post-OOBE.ps1 удаляет их. На Windows 10
  сохранялась только одна копия. В 24H2 при пустом пароле Windows не требует контрольных вопросов
  (они появляются только при создании учётной записи через экран OOBE).
- Проверка:
  ```powershell
  Get-LocalUser Admin, User | Select-Object Name, Enabled, PasswordRequired, PasswordExpires
  Get-LocalGroupMember -SID S-1-5-32-544   # Administrators
  Get-LocalGroupMember -SID S-1-5-32-545   # Users
  ```
- Откат: `Remove-LocalUser`, либо переименование через `Rename-LocalUser`. Профили удаляются через
  Свойства системы → Профили пользователей.

## Компонент FirstLogonCommands

Не используется. В оригинале он включал сетевые адаптеры после OOBE; в нашей схеме адаптеры
не отключаются, а действия первого входа выполняет Active Setup (раздел 15), который срабатывает
для каждого пользователя, а не только для первого вошедшего.
