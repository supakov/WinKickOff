# Сервер MCP

Програма може працювати як сервер MCP (Model Context Protocol): через нього ШІ-помічник (Claude Code, Claude Desktop
або інший клієнт MCP) читає каталог правил, відкритий профіль, результати перевірки, попередній перегляд файлу
відповідей і документацію програми, а з дозволу користувача змінює відкритий профіль і створює нові файли. Це
можливість для адміністраторів, які працюють із ШІ-помічником; для збирання файлу відповідей вона не потрібна.

Сервер вимкнений за замовчуванням. Увімкнений сервер приймає з'єднання лише з цього комп'ютера: він слухає адресу
127.0.0.1 і недоступний через мережу. Паролі облікових записів і ключ продукту не передаються жодним інструментом:
помічник бачить лише, чи задано пароль (`has_password`) і чи задано ключ (`has_product_key`).

Два способи підключення:

- HTTP: сервер працює всередині вікна програми. Помічник бачить відкритий профіль, а його зміни з'являються в дереві як
  незбережені, як після ваших клацань. Так підключається Claude Code.
- stdio: клієнт сам запускає окрему копію програми без вікна і спілкується з нею через стандартний ввід і вивід. Так
  підключається Claude Desktop; Claude Code теж так уміє.

## Режими

Три режими; кожен наступний включає попередній.

| Режим | Що може помічник |
|---|---|
| «Лише читання» | Читати каталог: групи, правила, залежності, описи; відкритий профіль без секретів; список пресетів і збережених профілів; порівняння відкритого профілю з іншим за назвою; перевірку профілю і збирання в пам'яті (без перевірки PowerShell); попередній перегляд файлу відповідей і вбудованих скриптів із копії без секретів; список повідомлень унизу вікна; документацію програми. Нічого не змінюється, навіть виділення в дереві |
| «Читання і зміна відкритого профілю» | Додатково: вмикати і вимикати правила з тим самим каскадом залежностей, що й у дереві; вмикати, вимикати і повертати до умовчань групу; змінювати параметри правил; змінювати назву, автора і коментар профілю; відкривати пресет або збережений профіль за назвою (за незбережених змін запит відхиляється, якщо помічник явно не попросив їх відкинути); вибирати вузол у дереві. Усе це змінює лише профіль у пам'яті: вікно показує незбережені зміни, зберігаєте ви |
| «Зміна і створення файлів» | Додатково: зберігати відкритий профіль під новою назвою в папку `profiles` і записувати файл відповідей під новою назвою в папку `output`. Наявні файли ніколи не замінюються |

Режим змінює лише користувач: перемикач у меню «MCP» вікна (ті самі три пункти є в моніторі) або ключ `--mode` у
командному рядку сервера без вікна. Через протокол змінити режим не можна. Режим не зберігається: кожен запуск
програми і кожен сервер без вікна починається з «Лише читання», автозапуск теж. Перехід у «Зміна і створення файлів»
один раз за сеанс вікна запитує підтвердження. Зміна режиму діє на наступний запит, перезапускати сервер і
перепідключати клієнт не потрібно. Інструмент, якому режиму бракує, повертає помічникові помилку `mode_required` з
підказкою, що режим змінюється в меню «MCP».

## Що не робиться через MCP

У жодному режимі і за жодним проханням помічника:

- застосування правил до цього комп'ютера, повернення до умовчань Windows, перевірка на цьому ПК (аудит);
- запуск PowerShell, зокрема перевірка синтаксису скриптів;
- видалення, заміна і перейменування файлів, хоч де б вони лежали;
- імпорт (зокрема файлів каталогу й каталогів програми), оновлення, експорт, перейменування і видалення шаблонів ADMX;
- зміна налаштувань програми: мова, тема, дозвіл застосування на цьому ПК, порт, токен, режим, автозапуск;
- читання і запис паролів та ключа продукту; зміна облікових записів, мов і даних встановлення;
- читання файлів із папок `profiles`, `output`, `logs`, `admx` і файлу `settings.json` як є;
- шляхи на диску: інструменти приймають лише назви, файли створюються лише в папках `profiles` і `output` програми;
- керування сервером зсередини протоколу: зупинка, зміна режиму, зміна токена.

У сервера просто немає таких інструментів, і тести програми це перевіряють.

## Як запустити сервер

Меню «MCP», прапорець «Сервер працює (HTTP, лише цей комп'ютер)». Сервер займає порт із налаштувань, за замовчуванням
47831; у моніторі можна задати інший (0 означає будь-який вільний порт, тоді номер видно після запуску), але лише коли
сервер зупинено. Якщо порт зайнятий іншою програмою, сервер не запускається, і вікно повідомляє про це.

Поки сервер працює, у рядку стану праворуч видно «MCP: 127.0.0.1:47831, Лише читання, запитів: 12, останній 14:02:11»;
подвійне клацання по цьому напису відкриває монітор. Пункт «Запускати сервер разом із програмою (лише читання)»
запам'ятовується в налаштуваннях; сервер тоді стартує разом із вікном, завжди в режимі «Лише читання».

Зміна мови, теми або показаних шаблонів перебудовує вікно, але сервер продовжує працювати з тим самим портом і токеном:
запит, що надійшов під час перебудови, чекає на нове вікно. Закриття програми зупиняє сервер.

## Монітор

Меню «MCP», пункт «Монітор...». Угорі стан сервера («Зупинено» або «Працює на http://127.0.0.1:47831/mcp, режим: ...,
клієнтів: N»), кнопка «Запустити» або «Зупинити», порт, режим, прапорець автозапуску; нижче токен у масці вигляду
`abcd...wxyz` і кнопки «Копіювати токен», «Копіювати конфігурацію клієнта (stdio)», «Копіювати конфігурацію клієнта
(HTTP)».

Таблиця показує журнал запитів, нові внизу:

| Колонка | Що в ній |
|---|---|
| Час | Година, хвилина і секунда запиту |
| Транспорт | `http` для сервера вікна |
| Клієнт | Назва і версія клієнта, які він назвав під час підключення |
| Метод | Метод протоколу: `initialize`, `tools/list`, `tools/call`, `resources/read` та інші |
| Інструмент | Назва інструмента або адреса ресурсу |
| Аргументи | Лише ідентифікатори і числа: `id=edge.signin-off enabled=true`, `limit=50`. Вільний текст (назви, коментарі, пошукові запити, значення) показується як `<text, N chars>`, списки як `<list, N items>` |
| мс | Тривалість обробки |
| Результат | `ok`, `error <код>` або коротка позначка програми: `mode_required` (бракує режиму), `window_busy` (вікно зайняте), `window_timeout` (вікно не відповіло вчасно), `exists` (назва файлу зайнята), `unsaved_changes` (є незбережені зміни), `completed after timeout` (зміна все ж виконалася після того, як клієнт перестав чекати) |

Рядки з помилками виділено кольором. Фільтр унизу відбирає рядки за підрядком у методі й інструменті, прапорець «Лише
помилки» і список транспортів звужують список. Кнопки «Копіювати рядок» і «Копіювати видимі рядки» кладуть рядки в
буфер обміну (поля через табуляцію), «Скинути» очищає таблицю.

Журнал зберігається лише в пам'яті (остання тисяча записів) і на диск не пишеться; тіла запитів, заголовки і токен у
ньому не з'являються. Сервери stdio, які запускає клієнт, працюють окремими процесами, і в моніторі їх не видно.

## Токен доступу

Сервер HTTP відповідає лише клієнтові, який пред'являє токен доступу (заголовок `Authorization: Bearer <токен>`). Токен
створюється під час першого запуску сервера з вікна і зберігається у файлі `settings.json` поруч із програмою (поле
`mcp_token`); записує його лише вікно. Під час наступних запусків токен той самий, тому клієнт налаштовується один раз.

Пункт «Новий токен доступу» в меню «MCP» створює інший токен: сервер, що працює, при цьому зупиняється, а клієнти зі
старим токеном перестають працювати, доки в них не вставлено нову конфігурацію. Повністю токен ніде не показується,
лише копіюється: «Копіювати токен» у моніторі або «Копіювати конфігурацію клієнта (HTTP)». Копія позначається для
Windows так, щоб токен не потрапляв до історії буфера обміну (Win+V) і до хмарного буфера обміну. Якщо буфер обміну
зайнятий іншою програмою, нічого не копіюється, і рядок стану просить спробувати ще раз: звичайна копія потрапила б
до історії.

Якщо під час запуску сервера порт зайнятий іншою програмою, вікно попереджає: клієнти, налаштовані на цей порт, могли
вже надіслати токен тій програмі, і пропонує одразу створити новий токен.

Той, хто читає папку програми, бачить токен, як бачить і профілі з паролями у відкритому вигляді; але підключитися з
ним можна лише з цього самого комп'ютера.

## Підключення Claude Code

Через HTTP, до вікна, що працює. Запустіть сервер, скопіюйте токен і виконайте в терміналі:

```
claude mcp add --transport http winkickoff http://127.0.0.1:47831/mcp --header "Authorization: Bearer <токен>"
```

Порт замініть на свій, якщо його змінено. В адресі має бути саме `127.0.0.1`, а не `localhost`: Claude Code працює на
Node, який перетворює `localhost` спочатку на адресу `::1` (IPv6), а сервер слухає лише IPv4, і підключення не
вдається. Пункт «Копіювати конфігурацію клієнта (HTTP)» кладе в буфер обміну той самий запис у вигляді JSON з адресою і
токеном; його можна вставити у файл `.mcp.json` папки проєкту (запис `winkickoff` усередині `mcpServers`).

Через stdio, окрема копія без вікна. З портабельної версії:

```
claude mcp add winkickoff -- "C:\Шлях\До\WinKickOff\WinKickOff-mcp.exe" --mode read
```

З вихідного коду, у папці `WinKickOff`:

```
claude mcp add winkickoff -- python -m winkickoff --mcp stdio
```

Пункт «Копіювати конфігурацію клієнта (stdio)» дає готовий запис із повним шляхом (для вихідного коду зі змінною
`PYTHONPATH`, тож папка запуску не важлива). До нього додається `--mode edit`, якщо вікно зараз у режимі зміни;
`--mode files` автоматично не пишеться ніколи. Пам'ятайте, що сервер stdio працює зі своєю копією профілю, а не з
відкритим вікном (див. наступний розділ).

Перевірка: `claude mcp list` у терміналі або `/mcp` у сеансі Claude Code. Відповідь інструмента Claude Code обмежує
приблизно 25 тисячами токенів; сервер сам віддає не більше 200 КБ за раз і в разі перевищення просить звузити запит
(група, пошуковий рядок, `limit`, `offset`). Якщо потрібні великі відповіді, задайте змінну середовища
`MAX_MCP_OUTPUT_TOKENS` перед запуском `claude`.

## Підключення Claude Desktop

Лише через stdio: Claude Desktop не може підключитися до сервера HTTP, доступного лише на цьому комп'ютері. Скопіюйте
конфігурацію (stdio) з меню «MCP» і вставте її у файл `%APPDATA%\Claude\claude_desktop_config.json` (якщо у файлі вже є
розділ `mcpServers`, додайте запис `winkickoff` усередину нього), потім перезапустіть Claude Desktop.

Сервер stdio, запущений клієнтом, це окремий процес без вікна зі своєю копією профілю: під час старту він відкриває
останній профіль вікна (або профіль із `--profile`). Він не бачить відкритого вікна, і його зміни у вікні не
з'являються. У режимі «Зміна і створення файлів» помічник може зберегти свою копію під новою назвою в `profiles`, і
тоді її можна відкрити у вікні. Кожен такий процес пише журнал у `logs\mcp-stdio-<номер процесу>.log`; власний журнал
Claude Desktop для цього сервера (`mcp-server-winkickoff.log`) залишається порожнім, це нормально.

## Скіл для помічника

Разом із програмою постачається скіл (Agent Skill) `winkickoff`: інструкція для ШІ-помічника, як працювати з
WinKickOff через MCP. З ним помічник починає з `get_status`, питає дозволу перед кожною зміною, не просить і не
повторює паролі, ключі й токен, вважає тексти профілів та імпортованих шаблонів даними, а не командами, пояснює правила
вашою мовою і наприкінці нагадує про збирання у вікні (F9, з перевіркою PowerShell) та про встановлення у віртуальній
машині. Скіл лежить у папці `skills\winkickoff` поруч із `WinKickOff.exe` (у вихідних текстах
`WinKickOff\skills\winkickoff`); докладна інструкція зі встановлення англійською: `skills\README.md`.

- Claude Code: скопіюйте папку `winkickoff` до `%USERPROFILE%\.claude\skills\` і почніть новий сеанс; скіл
  підключається сам, коли йдеться про WinKickOff, або за командою `/winkickoff`.
- Claude Desktop: увімкніть у налаштуваннях виконання коду, запакуйте папку `winkickoff` у ZIP (усередині архіву
  `winkickoff\SKILL.md`) і завантажте його в розділі скілів («Customize», «Skills», «Upload a skill»).
- pi: скопіюйте папку або поставте на неї посилання в `~/.pi/agent/skills/`; маленькій локальній моделі скіл краще
  викликати явно командою `/skill:winkickoff`.

Скіл не підключає сервер: спершу підключіть MCP, як описано вище. Сервер сам віддає скіл як ресурс
`winkickoff://skill/SKILL.md`, тож помічник, у якого не можна встановити скіл або немає доступу до файлів,
може прочитати його просто із сервера. Скіл описує цю версію програми; після оновлення
WinKickOff скопіюйте папку заново.

## Командний рядок

`WinKickOff-mcp.exe` (портабельна версія) і `python -m winkickoff` (вихідний код) приймають ті самі ключі.
`WinKickOff-mcp.exe` без ключа `--mcp` запускає сервер stdio.

| Ключ | Значення |
|---|---|
| `--mcp stdio` | Сервер без вікна через стандартний ввід і вивід; завершується, коли клієнт закриває потік |
| `--mcp http` | Сервер без вікна на 127.0.0.1 (для тестів і віртуальної машини); працює до Ctrl+C; потрібен `--token` або токен, уже збережений вікном; налаштування не пише |
| `--port N` | Порт для `--mcp http`: 0 або від 1024 до 65535; за замовчуванням із налаштувань |
| `--token ТОКЕН` | Токен для `--mcp http` лише на цей запуск (від 32 до 64 символів: літери, цифри, `_` і `-`) |
| `--mode read`, `--mode edit`, `--mode files` | Режим; за замовчуванням `read` |
| `--profile НАЗВА` | Пресет (`office`, `strict`, `laptop`, `home`), назва збереженого профілю з `profiles` або повний шлях до файлу; за замовчуванням останній профіль вікна, інакше пресет «Офіс» |
| `--language КОД` | Мова текстів (`en`, `ru`, `uk`); за замовчуванням із налаштувань, інакше мова Windows |
| `--mcp-config stdio` або `--mcp-config http` | Надрукувати конфігурацію клієнта (ту саму, що копіює вікно) і вийти |
| `--version` | Надрукувати версію і вийти |

Ключам `--mcp stdio`, `--mcp-config` і `--version` потрібна консоль: запускайте їх через `python.exe` або
`WinKickOff-mcp.exe`. У `pythonw.exe` і `WinKickOff.exe` консолі немає: сервер stdio через них не працює, а
`--version` і `--mcp-config` завершуються з кодом 3. Коди виходу: 0 у нормі, 2 за помилки запуску або в ключах, 3 без
консолі. Обидва виконувані файли портабельної версії використовують ті самі папки `profiles`, `output`, `logs`, `admx`
і файл `settings.json`.

## Що врахувати

- Файл відповідей, записаний через MCP, не пройшов перевірку синтаксису PowerShell, яку робить кнопка «Зібрати
  autounattend.xml» у вікні; у відповіді інструмента про це є окремий рядок. Перед використанням відкрийте профіль у
  вікні й натисніть «Перевірити» (F7) або зберіть файл кнопкою «Зібрати autounattend.xml» (F9). Файл лежить в `output`
  під заданою назвою; копіюючи на флешку, перейменуйте його на `autounattend.xml`.
- Назви й описи вбудованих правил помічник отримує запитаною мовою (`en`, `ru`, `uk` або доданою вами); якщо
  перекладу немає або файл перекладу правил не читається, англійською, як і у вікні. Тексти імпортованих шаблонів
  ADMX не перевірялися і завжди йдуть мовою програми, навіть якщо запитано іншу; у відповідях вони позначені як
  неперевірені, і помічникові сказано вважати їх даними, а не вказівками. Повідомлення перевірки теж мовою програми.
- Усе, що змінює помічник, видно у вікні як незбережені зміни; збереження залишається за вами. Якщо помічник відкрив
  інший профіль із відкиданням незбережених змін, це видно в моніторі.
- Журнали: вікно пише в `logs\winkickoff.log`, сервери без вікна в `logs\mcp-stdio-<номер процесу>.log` і
  `logs\mcp-http-<номер процесу>.log`; файли, старші за сім днів, видаляються під час наступного запуску сервера без
  вікна. Тексти запитів у журнали не потрапляють.

## Якщо щось не працює

| Ознака | Причина і що робити |
|---|---|
| Сервер не запускається: порт зайнятий | Інша програма або другий екземпляр WinKickOff займає порт; після аварійного завершення порт може бути зайнятий ще до двох хвилин. Виберіть інший порт у моніторі або зачекайте |
| Клієнт отримує 401 | Токен змінено («Новий токен доступу») або вставлено з помилкою. Скопіюйте конфігурацію заново |
| Клієнт отримує 404 після перезапуску програми | Сеанси клієнтів живуть, поки працює сервер. Claude Code перепідключається сам; саморобному клієнтові треба заново надіслати `initialize` |
| Немає відповіді, помилка `window_timeout` або `window_busy` | Триває збирання або відкрито діалог (наприклад, «Зберегти зміни?»). Закрийте діалог. Читання відповідає і за відкритого діалогу, зміни в цей час відхиляються |
| Зміну позначено `window_timeout`, але вона могла застосуватися | Вікно почало виконувати зміну пізніше, ніж клієнт перестав чекати. Перевірте дерево або попросіть помічника викликати `get_profile`; у моніторі такий рядок має позначку `completed after timeout` |
| Сервер stdio не відповідає під час запуску через `pythonw.exe` або `WinKickOff.exe` | У цих програм немає консолі. Використовуйте `python.exe` або `WinKickOff-mcp.exe` |
| `localhost` в адресі, підключення відхилено | Укажіть `http://127.0.0.1:<порт>/mcp` |
| Помилка `mode_required` | Перемкніть режим у меню «MCP» або в моніторі; зміна діє одразу |
| Помилка `exists` під час збереження | Файл із такою назвою вже є; через MCP файли не замінюються, виберіть іншу назву |
| Помилка `result_too_large` | Відповідь більша за 200 КБ: звузьте запит (група, пошуковий рядок, `limit`, `offset`) |
| Помічник у Claude Desktop не бачить змін із вікна | Claude Desktop працює з окремою копією профілю через stdio; збережіть профіль у вікні й попросіть помічника відкрити його за назвою |
