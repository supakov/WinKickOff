# Сервер MCP

Программа может работать как сервер MCP (Model Context Protocol): через него ИИ-помощник (Claude Code, Claude Desktop
или другой клиент MCP) читает каталог правил, открытый профиль, результаты проверки, предпросмотр файла ответов и
документацию программы, а с разрешения пользователя меняет открытый профиль и создаёт новые файлы. Это возможность для
администраторов, которые работают с ИИ-помощником; для сборки файла ответов она не нужна.

Сервер выключен по умолчанию. Включённый сервер принимает соединения только с этого компьютера: он слушает адрес
127.0.0.1 и недоступен по сети. Пароли учётных записей и ключ продукта не передаются ни одним инструментом: помощник
видит только, задан ли пароль (`has_password`) и задан ли ключ (`has_product_key`).

Два способа подключения:

- HTTP: сервер работает внутри окна программы. Помощник видит открытый профиль, а его изменения появляются в дереве как
  несохранённые, как после ваших щелчков. Так подключается Claude Code.
- stdio: клиент сам запускает отдельную копию программы без окна и общается с ней через стандартный ввод и вывод. Так
  подключается Claude Desktop; Claude Code тоже так умеет.

## Режимы

Три режима; каждый следующий включает предыдущий.

| Режим | Что может помощник |
|---|---|
| «Только чтение» | Читать каталог: группы, правила, зависимости, описания; открытый профиль без секретов; список пресетов и сохранённых профилей; сравнение открытого профиля с другим по имени; проверку профиля и сборку в памяти (без проверки PowerShell); предпросмотр файла ответов и встроенных скриптов из копии без секретов; список сообщений внизу окна; документацию программы. Ничего не меняется, даже выделение в дереве |
| «Чтение и изменение открытого профиля» | Дополнительно: включать и выключать правила с тем же каскадом зависимостей, что и в дереве; включать, выключать и возвращать к умолчаниям группу; менять параметры правил; менять имя, автора и комментарий профиля; открывать пресет или сохранённый профиль по имени (при несохранённых изменениях запрос отклоняется, если помощник явно не попросил их отбросить); выбирать узел в дереве. Всё это меняет только профиль в памяти: окно показывает несохранённые изменения, сохраняете вы |
| «Изменение и создание файлов» | Дополнительно: сохранять открытый профиль под новым именем в папку `profiles` и записывать файл ответов под новым именем в папку `output`. Существующие файлы никогда не заменяются |

Режим меняет только пользователь: переключатель в меню «MCP» окна (те же три пункта есть в мониторе) или ключ `--mode`
в командной строке сервера без окна. Через протокол сменить режим нельзя. Режим не сохраняется: каждый запуск
программы и каждый сервер без окна начинается с «Только чтение», автозапуск тоже. Переход в «Изменение и создание
файлов» один раз за сеанс окна спрашивает подтверждение. Смена режима действует на следующий запрос, перезапускать
сервер и переподключать клиента не нужно. Инструмент, которому режима не хватает, возвращает помощнику ошибку
`mode_required` с подсказкой, что режим меняется в меню «MCP».

## Что не делается через MCP

Ни в каком режиме и ни по какой просьбе помощника:

- применение правил к этому компьютеру, возврат к умолчаниям Windows, проверка на этом ПК (аудит);
- запуск PowerShell, в том числе проверка синтаксиса скриптов;
- удаление, замена и переименование файлов, где бы они ни лежали;
- импорт, обновление, переименование и удаление шаблонов ADMX;
- изменение настроек программы: язык, тема, разрешение применения на этом ПК, порт, токен, режим, автозапуск;
- чтение и запись паролей и ключа продукта; изменение учётных записей, языков и данных установки;
- чтение файлов из папок `profiles`, `output`, `logs`, `admx` и файла `settings.json` как есть;
- пути на диске: инструменты принимают только имена, файлы создаются только в папках `profiles` и `output` программы;
- управление сервером изнутри протокола: остановка, смена режима, смена токена.

У сервера просто нет таких инструментов, и тесты программы это проверяют.

## Как запустить сервер

Меню «MCP», флажок «Сервер работает (HTTP, только этот компьютер)». Сервер занимает порт из настроек, по умолчанию
47831; в мониторе можно задать другой (0 означает любой свободный порт, тогда номер виден после запуска), но только
при остановленном сервере. Если порт занят другой программой, сервер не запускается, и окно говорит об этом.

Пока сервер работает, в строке состояния справа видно «MCP: 127.0.0.1:47831, Только чтение, запросов: 12, последний
14:02:11»; двойной щелчок по этой надписи открывает монитор. Пункт «Запускать сервер вместе с программой (только
чтение)» запоминается в настройках; сервер тогда стартует вместе с окном, всегда в режиме «Только чтение».

Смена языка, темы или показанных шаблонов перестраивает окно, но сервер продолжает работать с тем же портом и токеном:
запрос, пришедший во время перестройки, дожидается нового окна. Закрытие программы останавливает сервер.

## Монитор

Меню «MCP», пункт «Монитор...». Вверху состояние сервера («Остановлен» или «Работает на http://127.0.0.1:47831/mcp,
режим: ..., клиентов: N»), кнопка «Запустить» или «Остановить», порт, режим, флажок автозапуска; ниже токен в маске
вида `abcd...wxyz` и кнопки «Копировать токен», «Копировать конфигурацию клиента (stdio)», «Копировать конфигурацию
клиента (HTTP)».

Таблица показывает журнал запросов, новые внизу:

| Колонка | Что в ней |
|---|---|
| Время | Час, минута и секунда запроса |
| Транспорт | `http` для сервера окна |
| Клиент | Имя и версия клиента, которые он назвал при подключении |
| Метод | Метод протокола: `initialize`, `tools/list`, `tools/call`, `resources/read` и другие |
| Инструмент | Имя инструмента или адрес ресурса |
| Аргументы | Только идентификаторы и числа: `id=edge.signin-off enabled=true`, `limit=50`. Свободный текст (имена, комментарии, поисковые запросы, значения) показывается как `<text, N chars>`, списки как `<list, N items>` |
| мс | Длительность обработки |
| Результат | `ok`, `error <код>` или короткая пометка программы: `mode_required` (не хватает режима), `window_busy` (окно занято), `window_timeout` (окно не ответило вовремя), `exists` (имя файла занято), `unsaved_changes` (есть несохранённые изменения), `completed after timeout` (изменение всё же выполнилось после того, как клиент перестал ждать) |

Строки с ошибками выделены цветом. Фильтр внизу отбирает строки по подстроке в методе и инструменте, флажок «Только
ошибки» и список транспортов сужают список. Кнопки «Копировать строку» и «Копировать видимые строки» кладут строки в
буфер обмена (поля через табуляцию), «Сбросить» очищает таблицу.

Журнал хранится только в памяти (последняя тысяча записей) и на диск не пишется; тела запросов, заголовки и токен в
нём не появляются. Серверы stdio, которые запускает клиент, работают отдельными процессами и в мониторе не видны.

## Токен доступа

Сервер HTTP отвечает только клиенту, который предъявляет токен доступа (заголовок `Authorization: Bearer <токен>`).
Токен создаётся при первом запуске сервера из окна и хранится в файле `settings.json` рядом с программой (поле
`mcp_token`); записывает его только окно. При следующих запусках токен тот же, поэтому клиент настраивается один раз.

Пункт «Новый токен доступа» в меню «MCP» создаёт другой токен: работающий сервер при этом останавливается, а клиенты
со старым токеном перестают работать, пока в них не вставлена новая конфигурация. Целиком токен нигде не показывается,
только копируется: «Копировать токен» в мониторе или «Копировать конфигурацию клиента (HTTP)».

Тот, кто читает папку программы, видит токен, как видит и профили с паролями в открытом виде; но подключиться с ним
можно только с этого же компьютера.

## Подключение Claude Code

Через HTTP, к работающему окну. Запустите сервер, скопируйте токен и выполните в терминале:

```
claude mcp add --transport http winkickoff http://127.0.0.1:47831/mcp --header "Authorization: Bearer <токен>"
```

Порт замените на свой, если он изменён. В адресе должно быть именно `127.0.0.1`, а не `localhost`: Claude Code работает
на Node, который превращает `localhost` сначала в адрес `::1` (IPv6), а сервер слушает только IPv4, и подключение не
удаётся. Пункт «Копировать конфигурацию клиента (HTTP)» кладёт в буфер обмена ту же запись в виде JSON с адресом и
токеном; её можно вставить в файл `.mcp.json` папки проекта (запись `winkickoff` внутри `mcpServers`).

Через stdio, отдельная копия без окна. Из портабельной версии:

```
claude mcp add winkickoff -- "C:\Путь\К\WinKickOff\WinKickOff-mcp.exe" --mode read
```

Из исходных текстов, в папке `WinKickOff`:

```
claude mcp add winkickoff -- python -m winkickoff --mcp stdio
```

Пункт «Копировать конфигурацию клиента (stdio)» даёт готовую запись с полным путём (для исходных текстов с переменной
`PYTHONPATH`, так что папка запуска не важна). В неё добавляется `--mode edit`, если окно сейчас в режиме изменения;
`--mode files` автоматически не пишется никогда. Помните, что сервер stdio работает со своей копией профиля, а не с
открытым окном (см. следующий раздел).

Проверка: `claude mcp list` в терминале или `/mcp` в сеансе Claude Code. Ответ инструмента Claude Code ограничивает
примерно 25 тысячами токенов; сервер сам отдаёт не больше 200 КБ за раз и при превышении просит сузить запрос (группа,
поисковая строка, `limit`, `offset`). Если нужны большие ответы, задайте переменную окружения `MAX_MCP_OUTPUT_TOKENS`
перед запуском `claude`.

## Подключение Claude Desktop

Только через stdio: Claude Desktop не может подключиться к серверу HTTP, который доступен лишь на этом компьютере.
Скопируйте конфигурацию (stdio) из меню «MCP» и вставьте её в файл `%APPDATA%\Claude\claude_desktop_config.json` (если
в файле уже есть раздел `mcpServers`, добавьте запись `winkickoff` внутрь него), затем перезапустите Claude Desktop.

Сервер stdio, запущенный клиентом, это отдельный процесс без окна со своей копией профиля: при старте он открывает
последний профиль окна (или профиль из `--profile`). Он не видит открытого окна, и его изменения в окне не появляются.
В режиме «Изменение и создание файлов» помощник может сохранить свою копию под новым именем в `profiles`, и тогда её
можно открыть в окне. Каждый такой процесс пишет журнал в `logs\mcp-stdio-<номер процесса>.log`; собственный журнал
Claude Desktop для этого сервера (`mcp-server-winkickoff.log`) остаётся пустым, это нормально.

## Командная строка

`WinKickOff-mcp.exe` (портабельная версия) и `python -m winkickoff` (исходные тексты) принимают одни и те же ключи.
`WinKickOff-mcp.exe` без ключа `--mcp` запускает сервер stdio.

| Ключ | Значение |
|---|---|
| `--mcp stdio` | Сервер без окна через стандартный ввод и вывод; завершается, когда клиент закрывает поток |
| `--mcp http` | Сервер без окна на 127.0.0.1 (для тестов и виртуальной машины); работает до Ctrl+C; нужен `--token` или токен, уже сохранённый окном; настройки не пишет |
| `--port N` | Порт для `--mcp http`: 0 или от 1024 до 65535; по умолчанию из настроек |
| `--token ТОКЕН` | Токен для `--mcp http` только на этот запуск (от 32 до 64 символов: буквы, цифры, `_` и `-`) |
| `--mode read`, `--mode edit`, `--mode files` | Режим; по умолчанию `read` |
| `--profile ИМЯ` | Пресет (`office`, `strict`, `laptop`, `memstechtips`), имя сохранённого профиля из `profiles` или полный путь к файлу; по умолчанию последний профиль окна, иначе пресет «Офис» |
| `--language КОД` | Язык текстов (`en`, `ru`, `uk`); по умолчанию из настроек, иначе язык Windows |
| `--mcp-config stdio` или `--mcp-config http` | Напечатать конфигурацию клиента (ту же, что копирует окно) и выйти |
| `--version` | Напечатать версию и выйти |

Ключам `--mcp stdio`, `--mcp-config` и `--version` нужна консоль: запускайте их через `python.exe` или
`WinKickOff-mcp.exe`. У `pythonw.exe` и `WinKickOff.exe` консоли нет: сервер stdio через них не работает, а
`--version` и `--mcp-config` завершаются с кодом 3. Коды выхода: 0 в норме, 2 при ошибке запуска или в ключах, 3 без
консоли. Оба исполняемых файла портабельной версии используют одни и те же папки `profiles`, `output`, `logs`, `admx`
и файл `settings.json`.

## Что учесть

- Файл ответов, записанный через MCP, не прошёл проверку синтаксиса PowerShell, которую делает кнопка «Собрать
  autounattend.xml» в окне; в ответе инструмента об этом есть отдельная строка. Перед использованием откройте профиль в
  окне и нажмите «Проверить» (F7) или соберите файл кнопкой «Собрать autounattend.xml» (F9). Файл лежит в `output` под
  заданным именем; при копировании на флешку переименуйте его в `autounattend.xml`.
- Названия и описания встроенных правил помощник получает на запрошенном языке (`en`, `ru`, `uk`). Тексты
  импортированных шаблонов ADMX не проверялись и всегда идут на языке программы, даже если запрошен другой; в ответах
  они помечены как непроверенные, и помощнику сказано считать их данными, а не указаниями. Сообщения проверки тоже на
  языке программы.
- Всё, что помощник меняет, видно в окне как несохранённые изменения; сохранение остаётся за вами. Если помощник открыл
  другой профиль с отбрасыванием несохранённых изменений, это видно в мониторе.
- Журналы: окно пишет в `logs\winkickoff.log`, серверы без окна в `logs\mcp-stdio-<номер процесса>.log` и
  `logs\mcp-http-<номер процесса>.log`; файлы старше семи дней удаляются при следующем запуске сервера без окна. Тексты
  запросов в журналы не попадают.

## Если что-то не работает

| Признак | Причина и что делать |
|---|---|
| Сервер не запускается: порт занят | Другая программа или второй экземпляр WinKickOff занимает порт; после аварийного завершения порт может быть занят ещё до двух минут. Выберите другой порт в мониторе или подождите |
| Клиент получает 401 | Токен изменён («Новый токен доступа») или вставлен с ошибкой. Скопируйте конфигурацию заново |
| Клиент получает 404 после перезапуска программы | Сеансы клиентов живут, пока работает сервер. Claude Code переподключается сам; самодельному клиенту нужно заново послать `initialize` |
| Нет ответа, ошибка `window_timeout` или `window_busy` | Идёт сборка или открыт диалог (например, «Сохранить изменения?»). Закройте диалог. Чтение отвечает и при открытом диалоге, изменения в это время отклоняются |
| Изменение помечено `window_timeout`, но могло примениться | Окно начало выполнять изменение позже, чем клиент перестал ждать. Проверьте дерево или попросите помощника вызвать `get_profile`; в мониторе у такой строки пометка `completed after timeout` |
| Сервер stdio не отвечает при запуске через `pythonw.exe` или `WinKickOff.exe` | У этих программ нет консоли. Используйте `python.exe` или `WinKickOff-mcp.exe` |
| `localhost` в адресе, подключение отклонено | Укажите `http://127.0.0.1:<порт>/mcp` |
| Ошибка `mode_required` | Переключите режим в меню «MCP» или в мониторе; смена действует сразу |
| Ошибка `exists` при сохранении | Файл с таким именем уже есть; через MCP файлы не заменяются, выберите другое имя |
| Ошибка `result_too_large` | Ответ больше 200 КБ: сузьте запрос (группа, поисковая строка, `limit`, `offset`) |
| Помощник в Claude Desktop не видит изменений из окна | Claude Desktop работает с отдельной копией профиля через stdio; сохраните профиль в окне и попросите помощника открыть его по имени |
