# Автоматическая установка Windows 11 Pro для рабочих групп без домена

Версия 0.2 от 13.09.2026. Файл ответов `autounattend.xml` собран с нуля после критического разбора
[UnattendedWinstall](https://github.com/memstechtips/UnattendedWinstall). Разбор лежит в
`docs/01-critical-review.md`, черновик постановки задачи для конструктора в `docs/02-constructor-requirements-draft.md`.

## История версий

### 0.2 (13.09.2026): исправление сбоя первой установки

Первая установка с версией 0.1 (украинский ISO, Windows 11 Pro) прошла установщик и выбор редакции,
но упала после первой перезагрузки с сообщением о невалидном файле ответов (код 0x80220005).
Причина по логу `setuperr.log`: две команды в проходе specialize (извлечение скриптов и включение .NET 3.5)
были длиннее 259 символов, а это жёсткий предел Windows Setup для элемента Path.

Что изменено:

- команда извлечения скриптов укорочена до 213 символов, команда запуска настроек до 144;
- включение .NET 3.5 перенесено из XML внутрь скрипта (параметр `EnableNetFx3`);
- все команды в XML завершаются кодом 0, а внутри скрипта необработанные ошибки перехватываются
  и пишутся в лог, потому что ненулевой код любой команды прерывает установку;
- из компонентов XML убраны все комментарии (остался один в шапке файла);
- порядок элементов учётной записи приведён к примеру из документации Microsoft;
- задача планировщика создаётся через schtasks, а не через командлет, который зависит от WMI и в specialize ненадёжен;
- внешние утилиты (auditpol, wevtutil, net, schtasks, dism) вызываются напрямую, без cmd.exe и проблем с кавычками.

По итогам независимого критического разбора версии 0.2 (12 замечаний, ни одно не роняет установку) дополнительно:

- подкатегории аудита задаются по GUID, а не по английским именам: на украинской системе auditpol английские имена не принимает;
- задача очистки после первичной настройки создаётся из XML с разрешением работать от батареи (иначе на ноутбуке она не запустилась бы);
- срок действия паролей снимается ещё в specialize командой net accounts, а не только после первичной настройки;
- встроенные Администратор и Гость находятся по SID, потому что на украинском образе у них локализованные имена;
- ошибки извлечения или запуска скриптов в specialize пишутся в файл и переносятся в общий лог;
- «Русский (Украина)» проверяется на наличие раскладки после применения, иначе ставится обычный «Русский»;
- окно PowerShell во время установки скрыто;
- служба DiagTrack оставлена в ручном режиме, задачи оценки совместимости не отключаются: они нужны для предложений обновлений функций;
- политика отключения Copilot продублирована в профиль пользователя (в HKLM она не действует);
- у каждого пользователя свой лог первого входа.

Отклонены три предложения: автоотказ UAC для стандартного пользователя (см. ограничения ниже), пароль Admin
прямо в файле ответов (стартовые учётные записи по договорённости без паролей, к тому же пароль в файле хранится
открытым текстом) и замечание о политике DisableWindowsConsumerFeatures (на Pro не действует, но безвредна, оставлена).
Подробный отчёт: `docs/03-critic-report-v0.2.docx`.

## Что реализовано из стартового списка

| Пункт | Как сделано | Где в файле |
|---|---|---|
| 1. Убрать Winhance | Файл переписан целиком, сторонних инструментов и загрузок из интернета нет | весь файл |
| 2. Спулер печати | Служба Spooler принудительно Automatic, защита PrintNightmare включена | `Setup-System.ps1`, раздел 1 |
| 3. Admin и User без паролей | Локальные учётные записи в проходе oobeSystem, группы Administrators и Users, пустой пароль, срок действия пароля снят после OOBE | `<LocalAccounts>`, `Post-OOBE.ps1` |
| 4. Windows Update работает | Автоматическая установка, активные часы 08:00-20:00, обновления других продуктов Microsoft, службы обновления не отключаются | `Setup-System.ps1`, раздел 2 |
| 5. Антивирус работает | Defender не трогается в сторону ослабления, включены облачная защита, PUA, сетевая защита, правила ASR | `Setup-System.ps1`, раздел 3 |
| 6. Языки ввода EN, UK, RU (Украина) | Порядок задан для экрана входа и профиля по умолчанию; «Русский (Украина)» подставляется при первом входе каждого пользователя | `<InputLocale>`, `Setup-User.ps1` |
| 7. Не спрашивать ключ | Универсальный ключ Windows 11 Pro без активации; активация придёт по цифровой лицензии | `<ProductKey>` |
| 8. Только Pro, без окна выбора | Тот же ключ однозначно выбирает редакцию | `<ProductKey>` |

Язык интерфейса Windows берётся из ISO и не меняется. В файле он всё же указан (`<UILanguage>uk-UA</UILanguage>`,
под украинский ISO, с которого шла установка 13.09.2026): по документации Microsoft первичная настройка показывает
экран выбора языка и региона, если хотя бы одно из четырёх языковых значений в файле отсутствует. Если ISO на
другом языке, это значение нужно заменить на язык ISO (например `en-US`). Также заданы регион Украина,
формат дат и чисел uk-UA, кодовая страница для старых программ uk-UA (CP1251), часовой пояс Киев.

## Что установщик всё же спросит

Осталось два экрана, оба осознанно:

1. Язык установщика и раскладка на первом экране (зависит от ISO, будет параметром конструктора).
2. Выбор диска и раздела (автоматическая разметка стирает диск без вопросов, для живых ПК это опасно).

Всё остальное проходит без участия человека: лицензия, ключ, редакция, все экраны OOBE, создание учётных записей.

## Как применить

1. Скачать актуальный ISO Windows 11 с сайта Microsoft.
2. Записать носитель (Rufus, Media Creation Tool или Ventoy).
3. Положить `autounattend.xml` в корень USB-носителя. Установщик находит его сам.
4. Загрузиться с носителя, выбрать диск, дождаться рабочего стола.

Для Ventoy файл кладётся рядом с ISO и подключается через плагин Auto Install, для Rufus достаточно корня носителя.

## Как проверить файл до установки

Статическая проверка на любом ПК (ничего не меняет, только читает файл):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\Validate-Unattend.ps1
```

Проверяются пределы Windows Setup (длина команд, комментарии, коды возврата), полнота языковых
значений, учётные записи, синтаксис трёх встроенных скриптов и описания задачи планировщика.

## Как проверить (только на виртуальной машине)

Проверять на рабочем ПК нельзя. Нужна виртуальная машина Hyper-V или VirtualBox с новым виртуальным диском
и ISO Windows 11. После установки проверить:

```powershell
Get-Content C:\ProgramData\Unattend\Logs\Setup-System.log | Select-String 'ERROR|WARN'
Get-Content C:\ProgramData\Unattend\Logs\Setup-User.log
Get-Content C:\ProgramData\Unattend\Logs\Post-OOBE.log
Get-Service Spooler | Select-Object Status, StartType
Get-LocalUser Admin, User | Select-Object Name, Enabled, PasswordExpires
Get-LocalGroupMember Administrators; Get-LocalGroupMember Users
Get-WinUserLanguageList | Select-Object LanguageTag, InputMethodTips
Get-MpPreference | Select-Object PUAProtection, MAPSReporting, CloudBlockLevel, EnableNetworkProtection, AttackSurfaceReductionRules_Ids
Get-SmbServerConfiguration | Select-Object EnableSMB1Protocol, RequireSecuritySignature
Test-Path C:\Windows\Panther\unattend.xml
slmgr /dli
```

Ожидаемо: в логах нет ERROR, Spooler Running/Automatic, оба пользователя без срока действия пароля,
языки en-US, uk-UA, ru-UA, файла в Panther нет, ASR содержит 17 правил.

## Как менять поведение

Все переключатели собраны в блоке `$Config` в начале `Setup-System.ps1` внутри XML. Каждый параметр
снабжён комментарием. Список приложений для удаления в `$AppsToRemove`, правила ASR в `$AsrRules`.
Именно этот блок будет генерировать конструктор, остальной код меняться не должен.

## Известные ограничения и осознанные риски

- Пока у Admin нет пароля, стандартный пользователь User не сможет подтвердить запрос UAC учётными данными Admin:
  Windows не пускает учётные записи с пустым паролем никуда, кроме консольного входа, и запрос закончится ошибкой 1327.
  Это штатное поведение, оно исчезнет после назначения паролей отдельным проектом. Устанавливать программы до этого нужно из-под Admin.
- Admin и User стартовые учётные записи без паролей. Пароли, дополнительные пользователи и группы назначает отдельный
  проект после установки. До его применения Windows штатно не пускает по сети с пустым паролем, поэтому общие папки
  между ПК заработают после назначения паролей. Срок действия стартовых паролей снят, чтобы система не требовала смену через 42 дня.
- «Русский (Украина)» появляется у пользователя после первого входа (иногда после второго). До этого стоит обычный «Русский».
- Обход проверки TPM и Secure Boot оставлен ради старых ПК. На совместимом железе он ничего не ослабляет.
- SmartScreen в режиме Warn, а не Block: режим Block запрещал бы малораспространённые локальные программы.
- Контролируемый доступ к папкам (защита от шифровальщиков) выключен по умолчанию: ломает старые программы, которые пишут в Документы. Включается одним параметром.
- Правило ASR «блокировать редкие исполняемые файлы» работает в режиме аудита по той же причине.
- Копии файла ответов удаляются из `C:\Windows\Panther` через 2 минуты после завершения OOBE. Скрипты в `C:\ProgramData\Unattend` остаются для аудита, паролей в них нет.
