## 2. Порядок и зависимости

```
T01 ─┬─> T02 ─┬─> T03 ─> T04 ─┬─> T06 ─┬─> T07 ─> T08 ─┐
     │        │               │        │              ├─> T11 ─> T12 ─> T13
     │        └─> T05 ────────┘        └─> T09 ─> T10 ┘
     └─────────────────────────────────────────────────────> T14 (после T13)
```

- T05 (шаблоны) не зависит от схемы и может идти параллельно с T02-T04.
- T09 (окно) может начинаться после T03 (профиль), таблицы T10 после T04.
- Golden-тест (T06) обязателен до любых правок шаблона; он же защищает T05.

## 4. Определение готовности задачи

Задача считается выполненной, когда:

1. Код написан, проходит `ruff check` и `mypy --strict` (для `core`).
2. Тесты задачи написаны и проходят; общий `pytest` зелёный; покрытие `core` не ниже 80 %.
3. Golden-тест по-прежнему проходит (для любых задач после T06).
4. Файл задачи в `todo/` обновлён: статус, дата, что сделано, отклонения от плана.
5. `AGENTS.md` обновлён, если изменилась структура каталогов, команды запуска или тестов.
6. Нет длинных тире в коде, строках интерфейса и документации.

## 5. Ограничения исполнения

- Никакие тесты и запуски не меняют состояние рабочего ПК заказчика: только чтение. Приёмочные
  тесты и проверка портабельности в виртуальной машине.
- Правки шаблона (`templates/`) меняют выходной XML; каждая такая правка требует нового эталона
  golden и новой версии `templates/VERSION`, с записью в `docs/` (история версий в README).
- Версия Python 3.14 фиксируется в `pyproject.toml` (`requires-python = ">=3.14"`); при проблемах
  с PyInstaller допускается сборка на 3.13 без изменения кода (задача T12 это проверяет).
