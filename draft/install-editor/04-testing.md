# 04. Стратегия тестирования

Редакция 0.2 от 25.09.2026. Инструмент: `unittest` из стандартной библиотеки
(`python -m unittest discover -s tests`), совместимость с pytest сохраняется. Ни один тест не меняет
состояние машины: чтение файлов проекта, запись только во временные папки теста.

## 1. Уровни

| Уровень | Что проверяет | Где запускается |
|---|---|---|
| Каталог | Целостность `rules/*.toml`: уникальные id, существующие группы и зависимости, отсутствие циклов, допустимые типы действий и обязательные поля, заполненные описания, ссылки на существующие файлы справочника | Везде |
| Семантический golden | Каждое действие файла v0.2 присутствует в каталоге при пресете «Офис» с тем же значением | Везде |
| Резолвер | Каскад выключения и включения, конфликты, групповые операции, порядок применения | Везде |
| Профиль | Загрузка, сохранение, полнота, миграция, `unknown`, сравнение | Везде |
| Генератор | Детерминированность; только включённые правила в выходе; корректный порядок; подстановка параметров; экранирование; лимит 259; XML well-formed | Везде |
| Валидатор | Каждая проверка ловит свой плохой профиль или XML и молчит на хорошем | Везде |
| Внешняя проверка | Собранный XML проходит `tools/Validate-Unattend.ps1`; скрипты разбираются PowerShell 5.1 | Только Windows, пропуск без `powershell.exe` |
| UI дымовой | Окно создаётся скрытым, дерево строится, поиск фильтрует, флажок вызывает резолвер | Windows с дисплеем |
| Портабельность | Чек-лист в ВМ | Ручной |
| Приёмочный | Установка в ВМ, чек-лист README | Ручной |

## 2. Семантический golden (главный тест переноса)

1. `tests/v02_actions.py` разбирает `autounattend.xml` v0.2 (путь относительно корня репозитория):
   извлекает три скрипта из CDATA, находит вызовы `Set-Reg`, `Remove-Reg`, `Set-ServiceStart`,
   `Invoke-Exe` и приводит их к кортежам `("reg", path, name, kind, value)`, `("reg-remove", path, name)`,
   `("service", name, start)`, `("exe", file, args)`. Значения `$Config.X` и `$du` подставляются
   по известным умолчаниям v0.2.
2. Каталог с пресетом «Офис» разворачивается в такое же множество кортежей (параметры по умолчанию,
   `DU:` заменяется тем же способом).
3. Утверждение: множество v0.2 является подмножеством множества каталога; каждое отсутствие
   выводится с указанием ожидаемого правила. Действия типа `ps` сравниваются по нормализованному тексту
   для известных фрагментов (NetFx3, SMB1, приложения, куст профиля, задача Post-OOBE).
4. Обратная проверка (предупреждение, не ошибка): действия каталога, отсутствующие в v0.2, перечислены
   в выводе теста, чтобы новые правила добавлялись осознанно.

## 3. Тесты по модулям

### core/catalog.py

- Загрузка всех файлов `rules/`; число правил и групп больше нуля; каждое правило имеет действия.
- Ошибочные каталоги во временной папке: дубликат id, неизвестная группа, `requires` на несуществующее
  правило, цикл `a → b → a`, действие без обязательного поля, неизвестный тип действия, недопустимая
  фаза, параметр без умолчания: каждый даёт `CatalogError` с идентификатором и файлом.
- Индекс поиска содержит для правила его id, title, теги, summary и строки действий (путь, имя, команда).

### core/deps.py

- `a requires b`: выключение `b` выключает `a`; включение `a` включает `b`.
- Цепочка `a → b → c`: выключение `c` выключает `b` и `a`; список изменений содержит причины.
- `conflicts`: включение `x` выключает `y` и всех, кто требует `y`.
- Группа: выключение группы выключает правила группы и внешних зависимых.
- Идемпотентность: повторное выключение даёт пустой список изменений.
- `apply_order`: требуемое раньше требующего; порядок фаз соблюдён; правила одной фазы без
  зависимостей сохраняют порядок каталога.

### core/profile.py

- Профиль из каталога равен пресету «Офис» (файл `profiles/preset-office.json`).
- Цикл сохранение/загрузка даёт равный объект; ключи `rules` в порядке каталога.
- Профиль без части правил дополняется умолчаниями с предупреждениями; неизвестные в `unknown`.
- Миграция профиля формата 1 (по таблице `config → rules`) даёт ожидаемые состояния.
- `diff` двух профилей перечисляет отличия по правилам, параметрам и данным.

### core/render.py

- Два вызова на одном профиле дают одинаковые байты.
- Профиль с выключенным правилом: ни одна строка его действий не встречается в выходе; блок
  `# [id]` отсутствует.
- Фаза без правил: инфраструктура фазы отсутствует (нет Active Setup, нет задачи Post-OOBE).
- Параметры подставлены; строка с одинарной кавычкой экранирована.
- Все `Path` в XML не длиннее 259; XML разбирается `xml.etree`; профиль встроен и читается обратно.
- Сборка пресета «Офис» содержит все правила пресета по идентификаторам в комментариях.

### core/validate.py

Один плохой профиль или XML на каждую строку таблицы из постановки 3.5; хороший профиль даёт
ноль ошибок. Отдельно: выключенное базовое правило даёт предупреждение; включённое рискованное даёт
предупреждение с текстом риска.

### core/importer.py

- Импорт XML с встроенным профилем возвращает равный профиль.
- Импорт файла v0.2 без встроенного профиля даёт профиль, равный пресету «Офис» по правилам
  (через сопоставление действий); несопоставленные действия перечислены.

### core/pscheck.py

- Без `powershell.exe` результат «пропущено»; с ним синтаксическая ошибка обнаруживается.

### ui

- `MainWindow` с `withdraw()`: дерево содержит все группы и правила; поиск «PUAProtection» оставляет
  одно правило; переключение узла меняет профиль и перерисовывает зависимые; параметр в панели
  меняет профиль. Тесты помечены и пропускаются без дисплея (`tk.TclError`).

## 4. Чек-лист портабельности и приёмочный тест

Без изменений относительно редакции 0.1 (раздел 4 и 5 старого документа): чистая ВМ, запуск с
флешки, снимки реестра и `%APPDATA%` до и после, перенос папки, удаление без следов; приёмочная
установка Windows 11 с файлом из пресета «Офис» по чек-листу README.

## 5. Организация

- `python -m unittest discover -s tests -v` в папке `WinKickOff/`; `tools/run-tests.ps1` делает то же
  и дополнительно запускает `tools/Validate-Unattend.ps1` на собранном файле.
- Покрытие (при наличии `coverage` в ВМ): `core` не ниже 80 %.
- Тесты не пишут за пределы `tempfile.TemporaryDirectory()`.
