# 04. Стратегия тестирования

## 1. Уровни

| Уровень | Что проверяет | Инструмент | Где запускается |
|---|---|---|---|
| Модульные | Каждый модуль `core/` изолированно | pytest | Локально и в чистом venv на 3.14 |
| Golden | Генератор воспроизводит эталон v0.2 побайтно | pytest, сравнение файлов | То же |
| Валидатор | Каждая проверка ловит свой плохой профиль и не ругается на хороший | pytest, файлы `tests/profiles/bad-*.json` | То же |
| Внешняя проверка | Собранный XML проходит `tools/Validate-Unattend.ps1` | pytest вызывает `powershell.exe`, пропуск если недоступен | Только Windows |
| UI дымовой | Окно создаётся, все страницы строятся, привязки работают, сборка из UI даёт тот же XML | pytest с `tk.Tk()` и `withdraw()` | Windows с дисплеем |
| Портабельность | Сборка запускается с флешки на чистой машине, ничего не пишет вне своей папки | Ручной чек-лист | Виртуальная машина |
| Приёмочный | Установка Windows 11 с собранным файлом проходит без вопросов, чек-лист README | Ручной | Виртуальная машина |

Ни один тест не изменяет состояние машины, на которой запускается: никакого реестра, служб,
языков. Это правило проекта (рабочий ПК заказчика неприкосновенен).

## 2. Модульные тесты по модулям

### core/paths.py

- В режиме исходников `root` равен корню репозитория; в «замороженном» режиме (подмена `sys.frozen`
  и `sys.executable` через monkeypatch) `root` равен папке exe.
- Папки `profiles`, `output`, `logs` создаются; повторный вызов идемпотентен.
- Относительные пути внутри `root` сериализуются относительно, внешние абсолютно.

### core/schema.py

- Схема загружается; у каждого параметра есть `id`, `group`, `type`, `default`, `label.ru`, `doc`.
- Все `group` существуют; все `doc` указывают на существующие файлы в `docs/reference/`.
- `enum` содержит `default` среди `values`; `int` имеет `min <= default <= max`.
- Идентификаторы уникальны; порядок сохраняется.
- Тест синхронизации: множество ключей `$Config` в `templates/Setup-System.template.ps1`
  (после подстановки умолчаний) равно множеству параметров с `target: config`.

### core/profile.py

- Профиль из умолчаний равен пресету «Офис».
- Сохранение и загрузка дают равный объект; порядок ключей в файле соответствует схеме.
- Загрузка профиля без части ключей дополняет умолчаниями и возвращает список предупреждений.
- Неизвестные ключи попадают в `unknown` и переживают цикл сохранения.
- `diff(a, b)` возвращает список отличий с путями параметров.
- Миграция с `template_version` 0.1 → 0.2 добавляет новые параметры.

### core/render.py

- Golden: профиль «Офис» → текст, равный `tests/golden/autounattend-v0.2.xml` (сравнение байтов,
  CRLF, без BOM).
- Сериализация значений PowerShell: `True` → `$true`, `'It''s'` экранирование, список с отступами.
- Учётные записи: порядок элементов, пустой пароль, три записи, arm64-копия идентична amd64.
- Языки: `ru-UA` заменяется на `0419:00000419` в XML и присутствует в списке для Setup-User.
- Пустой `bypass_checks` не выводит `RunSynchronous`.
- Правило ASR с режимом 0 отсутствует в `$AsrRules`.
- Длина каждой строки `Path` в результате не превышает 259 для всех пресетов.

### core/validate.py

Для каждой проверки из постановки, раздел 3.4: один плохой профиль или XML в `tests/profiles/`
и утверждение, что возвращается `Issue` нужного уровня с нужным `field`. Отдельно: хороший профиль
даёт пустой список ошибок (предупреждения допустимы). XML-проверки на подготовленных строках:
комментарий внутри компонента, `Path` 260 символов, отсутствующий `UILanguage`.

### core/importer.py

- Разбор блока `$Config` из эталона v0.2 даёт словарь, равный умолчаниям схемы.
- Разбор `$AppsToRemove` и `$AsrRules` даёт списки из эталона.
- Файл без блока `$Config` возвращает ошибку, а не исключение.
- Изменённое значение в XML (например `ControlledFolderAccess = 1`) попадает в профиль.

### core/pscheck.py

- Если `powershell.exe` отсутствует (monkeypatch `shutil.which`), функция возвращает «пропущено».
- На Windows: скрипт с синтаксической ошибкой даёт ненулевой результат с текстом ошибки.

### core/i18n.py

- Каждая строка есть в `ru` и `uk`; нет строк с длинным тире; плейсхолдеры `{}` совпадают по языкам.

## 3. Тесты UI

- Создание `MainWindow` с `root.withdraw()`; обход всех групп дерева строит страницы без исключений.
- Изменение `tk.BooleanVar` параметра меняет профиль и ставит «грязный» флаг.
- Кнопка «Сбросить группу» возвращает умолчания.
- Команда «Собрать» из UI с профилем «Офис» даёт файл, равный golden (через ту же функцию `render`,
  тест проверяет, что UI ничего не добавляет).
- Тесты помечены `@pytest.mark.ui` и пропускаются, если нет дисплея (`tk.TclError`).

## 4. Чек-лист портабельности (ручной, перед выпуском)

1. Скопировать `dist/InstallEditor` на флешку, запустить на чистой ВМ Windows 11 без Python.
2. Приложение открывается за 2 секунды, без консольного окна.
3. Рядом появились `profiles/`, `output/`, `logs/`, `settings.json`; в `%APPDATA%`, `%LOCALAPPDATA%`,
   `%PROGRAMDATA%` и реестре (`HKCU\Software`) новых записей нет (сравнение снимков до и после).
4. Сохранить профиль, собрать XML в `output/`, открыть папку кнопкой.
5. Переместить папку приложения в другое место, открыть недавний профиль: путь разрешается.
6. Закрыть, удалить папку: следов не остаётся.

## 5. Приёмочный тест (ручной, на каждый выпуск шаблона)

Установка Windows 11 Pro в ВМ с файлом, собранным из пресета «Офис», затем чек-лист из
корневого README проекта (логи без ERROR, Spooler, учётные записи, языки, Defender, SMB, Panther).

## 6. Организация

- `pytest -q` запускает всё, кроме `ui` и `external` без явных маркеров; `pytest -m "ui or external"`
  на Windows с дисплеем.
- Покрытие `pytest --cov=install_editor.core --cov-fail-under=80`.
- `ruff check` и `mypy install_editor/core --strict` как часть тестового прогона.
- Тесты не пишут за пределы `tmp_path`.
